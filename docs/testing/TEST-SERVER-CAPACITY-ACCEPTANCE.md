# 测试服务器容量与故障验收标准

状态：待执行；所有阈值仅用于专用匿名测试服务器的首轮容量演练，不能外推为生产 SLA 或真实付费 ASR 承诺。

## 管理控制台专属边界

容量监控、压测/停止、峰值、长稳、故障注入和报告的 UI/控制面唯一归属管理员 `system-frontend` / ControlShell，可复用 `/servers`、`/logs` 或后续经过 UI 设计批准的管理员测试容量入口。员工 `frontend` / AppShell 不得新增任何相关入口、按钮、状态、脚本、测试文案或浏览器端状态源。

员工站最多作为现有业务路径的被动受测对象，用于证明其无法读取管理员运行/容量事实和无法发起控制命令；其请求不作为容量控制面，也不得将监控或停止门投影给员工。

## 1. 适用边界

- 目标必须是 Debian 12 专用测试主机，单公网 IP 承载 `work`、`admin`、`api`；PostgreSQL 不得公开暴露。
- API、两个前端、PostgreSQL、获准的 Worker 和 Nginx 使用同一冻结代码快照；测试库必须从空库迁移并精确回收。
- 数据仅为匿名 A/B 项目、匿名员工/管理员和小型 fake/stub 数据。禁止视频、音频、SRT 正文、术语正文、Cookie/Auth、Secret、objectKey、连接串和供应商原始载荷。
- 默认 fake/stub 必须零网络。真实 ASR/COS/Sentry/Secret/供应商、购买、部署发布和生产压测一律为 NO-GO。
- worker、队列、运行记录与日志的权威状态仍来自后端/PostgreSQL；压测工具、浏览器和 Nginx 不得自建业务状态。

## 2. 指标定义与采样

| 类别 | 必采指标 | 采样/证据 | 说明 |
| --- | --- | --- | --- |
| API | RPS、p50/p95/p99、状态码、超时、错误率 | 每档 1 分钟桶 + 总计 | 分开报告读、写和 fake/stub 延迟 |
| 主机 | CPU、内存、Swap、磁盘使用率、磁盘 I/O 等待、网络吞吐/错误 | 每 5 秒采样，1 分钟聚合 | 所有时间使用同一时钟基准 |
| PostgreSQL | 活跃/空闲连接、连接上限使用率、慢查询、锁等待、事务失败、数据库可用性 | 每 5 秒 | 不记录 SQL、连接串或业务参数 |
| 队列/Worker | 队列深度、入/出速率、最老任务等待、运行数、租约超时、重启次数、失败/unknown 数 | 每 5 秒 | 缺指标应标 `unknown`，不得记 0 |
| 业务安全 | 幂等冲突、重复命令数、unknown 后写次数、跨项目/跨站拒绝数、迟到响应丢弃数 | 每个阶段汇总 | 容量事实只呈现于管理员控制台；费用相关写入必须为 0 次重复 |
| 恢复 | 故障检测、服务恢复、队列回落、数据对账时长 | 故障逐项记录 | 从注入时刻开始计时 |

延迟仅统计完成的同类请求；客户端取消、受控网络丢包、fake/stub 人为延迟和服务端应用耗时必须分别标注，不能混算成应用 p95。

## 3. 通过门与停止门

### 3.1 正常档通过门（S0–S3）

- 业务错误率低于 `1%`，且无权限泄露、跨项目污染、重复写入、费用风险或未分类 5xx。
- p95 小于 `1.5s`，p99 小于 `3s`；受控 stub 延迟另行展示，不作为应用回归的掩护。
- CPU 平均低于 `70%`，内存低于 `70%`，Swap 不增长，磁盘使用率低于 `80%`。
- PostgreSQL 连接上限使用率低于 `70%`，无持续锁等待/连接耗尽；队列在稳定档没有持续增长。
- Worker 无非预期退出；所有完成、失败、unknown 和重启后恢复的任务均可从同一身份读取。

### 3.2 压力/峰值通过门（S4–S5）

- 压力档错误率低于 `3%`，峰值档低于 `5%`；错误必须能归类为受控 429、5xx、超时、拒绝或已知资源限制。
- p95 低于单用户基线的 `3 倍`，p99 不超过 `10s`；无连续超时风暴。
- 峰后 15 分钟内，队列回到峰前稳定区间或所有任务进入可解释终态；未出现重复副作用。
- Nginx、API、Worker 和 PostgreSQL 没有不可恢复重启循环；admin 临时安全门和两站隔离持续有效，且员工站没有容量控制/运行事实入口。

### 3.3 长稳通过门（1–4 小时）

- 在冻结并发档持续运行，内存、PG 连接、队列深度和文件描述符没有连续 30 分钟单向增长。
- 整体错误率低于 `1%`，p95/p99 未连续 15 分钟超过同档前 30 分钟中位值的 `2 倍`。
- 没有任务永久运行、未解释 unknown、孤儿 Worker、数据库残留或跨 A/B 项目状态。
- 测试结束可完整回收，且只删除本轮精确命名的数据库、夹具、服务和临时访问资产。

### 3.4 立即停止门

命中任意一项，立刻停止继续升压/故障组合，保留脱敏证据并按运行手册回滚：

| 类别 | 停止条件 |
| --- | --- |
| 数据与安全 | 生产目标、真实外网/付费服务、Secret、Cookie/Auth、对象键或正文进入测试；任意越权、A/B 串数据、重复副作用或费用风险 |
| 主机 | CPU 连续 5 分钟 `>=85%`；内存连续 5 分钟 `>=80%` 或 Swap 持续增长；磁盘 `>=80%`；I/O 等待持续恶化 |
| API | 正常档错误率 `>=2%`、压力档 `>=5%`，或 p95 连续 5 分钟超过基线 `3 倍`、p99 超过 `10s` |
| PostgreSQL | 连接使用率 `>=80%`、连接耗尽、死锁/锁等待持续增长或数据库不可恢复 |
| 队列/Worker | 队列持续 10 分钟增长无回落、最老任务等待超过冻结上限、Worker 重启循环、任务重复执行或无法对账 |
| 过程 | 无法采集关键指标、测试数据不再可精确回收、停止脚本/人工停止路径失效 |

## 4. 并发与场景矩阵

| 阶段 | 并发 | 主要流量 | 最少验收 |
| --- | ---: | --- | --- |
| 烟雾 | 1 | work/admin/api 健康、一次读写/恢复 | 两站权限、A/B 隔离、零网络 fake |
| 基线 S0 | 1 | 固定混合读写 | 延迟/资源基线、幂等命令=1 |
| S1 | 5 | 约 80% 读、20% 有界写 | 查询/任务中心/Worker 基本稳定 |
| S2 | 10 | 同 S1，增加刷新/分页 | 迟到响应不覆盖新查询 |
| S3 | 25 | 同 S2，增加并行项目 A/B | 首个容量拐点与队列回落 |
| S4 | 50 | 压力混合 | 资源、连接、错误分类、恢复 |
| S5 | 100 | 5–10 分钟峰值 | 峰值、降级与停止门 |
| 长稳 | 10–25 | 冻结混合比例，1–4 小时 | 泄漏、积压、重启恢复 |

写路径的混合比例必须由后端确认其为安全、可回收、零费用的 fake/stub 场景。若测试框架无法控制稳定命令 ID、响应丢失或同身份 GET，写负载不允许开始。

## 5. 故障注入验收

| 编号 | 故障 | 预期 | 必要证据 |
| --- | --- | --- | --- |
| FI-01 | 测试 PostgreSQL 短断 | API 明确失败/stale，恢复后连接池和任务状态一致 | 注入/恢复时刻、requestId 哈希、连接/队列曲线 |
| FI-02 | 指定 Worker 退出 | 租约可接管或任务稳定终态；无双执行 | workerId 哈希、重启次数、任务身份与 Attempt 计数 |
| FI-03 | fake/stub 429 | 受控失败/退避，不能重发可能收费写 | 单命令 ID 的 POST=1 与 GET 恢复记录 |
| FI-04 | fake/stub 5xx/超时 | 可读错误分类、唯一恢复动作、队列有界 | 状态码、耗时、错误率和回落时间 |
| FI-05 | 服务端完成后响应丢失 | 客户端只 GET 同一身份，不创建第二任务 | 同一资源/命令 ID 的请求序列 |
| FI-06 | 旧查询迟到 | 新 A/B 项目、筛选/分页或权限身份不被覆盖 | 查询身份哈希、前端状态与请求顺序 |
| FI-07 | API/Worker 重启 | 重启后从 PostgreSQL 恢复，任务中心一致 | 重启时间、恢复时间、无重复写证明 |

故障注入前后均需核对：容量观测与控制仍只在管理员 ControlShell，员工站与管理站权限隔离、A/B 项目隔离、任务中心列表/详情与后端读模型一致、unknown 只读恢复、无自动重发写命令。

## 6. 容量结论的写法

报告必须按“在何种条件下”给出结论，至少含：

1. 测试主机脱敏规格、代码快照、Node/pnpm/PostgreSQL/Nginx 版本、fake/stub 配置、数据库连接池和获准 Worker 数。
2. 最后一个完整通过档、首个停止档或首个性能拐点；不得把短时峰值写成持续容量。
3. 推荐配置按 `CPU / 内存 / 磁盘类型与可用容量 / 网络 / PostgreSQL 连接上限 / Worker 数` 表示，并区分“已证明”和“待真实供应商验证”。
4. 瓶颈归类为 API、Nginx、PostgreSQL、Worker、队列、磁盘、网络或测试工具；未知则明确为未知。
5. 风险：目前没有真实认证、真实对象存储、外部监控 Agent、真实付费 ASR 或完整 Worker 启动契约时，不能承诺生产安全性、真实成本或供应商容量。
6. CNY 台账：实际费用、预算、未对账金额和发生原因。无外部资源时明确记为 `¥0`，不以“免费”替代记录。

## 7. 最终交付与回收验收

容量任务只有同时满足以下条件才能交规划审核：

- 已输出脱敏的烟雾、基线、阶梯、压力/峰值、长稳（若执行）和故障矩阵结果；未执行项写明原因。
- 已列出 P0–P3、停止门命中、未解决依赖、建议主机规格及不能外推的范围。
- 已停止负载、API、Worker 与临时 Nginx 配置；已撤销隧道、临时 admin 访问门、临时 SSH 公钥和测试 DNS（如有）。
- 已精确删除匿名测试库、夹具和临时文件，确认 PostgreSQL 不开放公网且无本轮残留监听；不删除任何未确认归属的文件或数据。
- 已保留的证据不含敏感资料，保留期和责任人明确；所有费用以 CNY 结算或标记待对账。

未满足任一项时，结论只能是“测试未关闭”，不得宣称已部署、已通过压测或可用于生产。
