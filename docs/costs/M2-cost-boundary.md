# M2 技术成本边界

状态：2026-08-12 规划报价；创建资源前重新核对控制台价格。
换算：为便于预算，统一按 `1 USD ≈ 7.2 CNY` 估算，不代表信用卡最终汇率、税费或发票金额。

## 估算口径

- 员工不超过 10 人，同时上传或工作批次 5–6 个。
- 单项目或批次 10–30 GB；以下按总日上传量估算，不假定每个文件都是 30 GB。
- 原始素材默认进入回收站后保留 48 小时，因此稳定状态平均存储量约为两天上传量。
- R2 使用 Standard：`0.015 USD/GB-month`，每月免费 10 GB-month；Class A 每月免费 100 万次，超出后 `4.50 USD/百万次`；出口流量免费。
- 默认分片 64 MiB。按当前剧集和容量结构，低、中、高档的分片创建、上传和完成操作通常仍在每月 100 万次免费额度内；大量重试或极高积单需要另计。
- 不含 ASR、OCR、LLM、域名、短信、办公宽带、税费以及人工运维成本。

## 存储容量

| 档位 | 示例日上传量 | 48 小时平均存储 | R2 Standard 估算/月 |
| --- | ---: | ---: | ---: |
| 开发测试 | 偶发一次 10–30 GB | 小于 10 GB-month 计费均值 | `0 USD`，通常在免费额度内 |
| 低 | 100 GB/日 | 200 GB | 约 `2.85 USD` |
| 中/平衡 | 300 GB/日 | 600 GB | 约 `8.85 USD` |
| 高 | 600 GB/日 | 1.2 TB | 约 `17.85 USD` |
| 极高积单 | 1.2 TB/日 | 2.4 TB | 约 `35.85 USD`，操作费另预留 `4.50–9 USD` |

计算方法：`(平均存储 GB - 10 GB 免费额度) × 0.015 USD`。实际按每天峰值平均和供应商取整规则结算。

## 整体月成本

| 阶段 | Railway | Neon PostgreSQL | R2 | Access | 合计 USD/月 | 预算人民币/月 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| M2开发测试 | `5–10` | `0` Free | `0–1` | `0` | `5–11` | 约 `36–80元` |
| 低量公司试用 | `20–30` Pro | `10–20` Launch | `3` | `0` | `33–53` | 约 `238–382元` |
| 中量平衡档 | `20–35` | `15–25` | `9` | `0` | `44–69` | 约 `317–497元` |
| 高量 | `25–45` | `15–30` | `18–23` | `0` | `58–98` | 约 `418–706元` |
| 极高积单 | `40–80` | `25–50` | `40–45` | `0` | `105–175` | 约 `756–1260元` |

Railway Pro 最低 `20 USD/月` 且包含同额资源用量；本项目的文件不经过 Railway，因此 Railway 成本主要来自 API 内存、少量 CPU 和 Cron。Neon Launch 官方示例的典型间歇负载约 `15 USD/月`，实际通过自动缩放上限和闲置缩容控制。

## 动态调节规则

- 测试阶段先设总预算上限 `15 USD/月`，只上传匿名合成文件。
- 公司试用阶段默认上限 `70 USD/月`，覆盖中量平衡档；R2、Railway、Neon分别设置告警或计算上限。
- 连续 7 天存储峰值超过 1.2 TB，先检查是否按 48 小时清理成功，再考虑提高预算；禁止先加服务器掩盖清理故障。
- API CPU 持续高于 70% 或延迟超标后再增加 Railway 副本；文件上传速度慢时先检查办公室上行和 R2 网络，不盲目增加 API CPU。
- 数据库只存元数据。若数据库体积异常增长，先审计日志、历史状态和索引，不把视频或大结果写入 PostgreSQL。
- ASR/OCR 接入时建立独立月预算和用量表，不混入本表，也不复用本表的自动扩容授权。

## 购买前门槛

1. 用户确认本报价和测试上限。
2. 创建私人 GitHub 和远程仓库，启用最小 CI；单独取得推送授权。
3. 用户明确授权创建 Railway、Neon、Cloudflare 资源及绑定支付方式。
4. 在代表性办公网络完成 R2 1 GB 与 10 GB 上传测试。
5. 网络测试通过后才把 R2 作为公司试用存储；失败则退回规划重新比较区域供应商。
