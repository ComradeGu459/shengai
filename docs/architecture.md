# 架构边界草案

状态：里程碑 2 范围与本地技术路径已确认；首期公网身份入口和“两站一后台”边界已确认，真实云资源和识别供应商尚未创建或定稿。

## 项目说明

目标用户是海外短剧字幕与术语审改人员。云端版要把项目、素材、识别任务、术语候选、人工审改、证据和导出纳入可协作、可审计、可恢复的流程，同时保持原始输入只读。

里程碑 1 的成功标准已经满足：独立仓库、清晰目录、固定工具、可运行骨架、数据防误提交规则和真实验证。当前非目标仍包括迁移旧数据、实现完整业务、接入付费识别 API 和正式发布。

## 已确认的首个业务切片

里程碑 2 实现：创建项目 → 创建上传会话 → 获取对象存储短时分片直传授权 → 上传并恢复 → 服务端完成和校验 → 项目进入可处理状态 → 项目移入回收站、恢复或到期清理。

首批页面固定为：

1. 项目中心：创建、检索、打开项目并查看生命周期状态。
2. 上传任务：查看文件、分片进度、失败原因以及暂停、继续和重试操作。
3. 回收站：查看到期时间、恢复项目和后台清理结果。

ASR、OCR、术语 AI、复杂审改、账号管理和正式交付不进入这条链路。

上传任务、后续任务中心和项目工作台是三个不同边界：上传任务只传输素材；任务中心只汇总 ASR/OCR/AI/导出等异步执行事实；项目工作台承载术语确认、识别结果查看、人工审改、验收和交付。完整的 UI、前端、后端、数据所有权与允许目录以 `docs/contracts/MODULE_RESPONSIBILITY_MATRIX.md` 为准。

## 模块化单体

后端保持一个代码库和一套领域模型，按业务能力划分模块。部署时可以把 HTTP 入口和 Worker 进程分开扩容，但不拆成独立业务服务。

## 两站一后台与访问边界

员工工作台和系统控制台是两个独立前端入口，不是两个独立业务后端：

- 员工工作台提供项目生产流程；系统控制台提供引擎/API、配置、预算、日志和服务器运行管理。两边使用独立模块注册表和路由，员工站不得显示控制台入口。
- 首期通过 Cloudflare Tunnel 暴露公网域名，通过两个 Cloudflare Access Application 分别保护员工站和控制台。员工站允许显式登记的员工邮箱，控制台只允许部署所有者的精确邮箱。
- HTTP 后端分为业务 API 与管理 API 访问域，分别校验 Access JWT 的签名、issuer、audience 和有效期；管理 API 不能因为请求来自同一前端服务器就跳过授权。
- 外部身份的稳定标识和邮箱可以写入操作审计，但不建立应用内密码、邀请和成员生命周期。未来账号体系加入时，通过身份映射迁移，不改变历史命令和审计主体。
- 两个前端、HTTP 后端和 Worker 首期可部署在同一台服务器或同一组资源；扩容按 HTTP、ASR/OCR Worker、媒体转码、数据库和对象存储的实际压力分别进行，不按网站数量机械购买服务器。

引擎、API、提示词/热词、服务器和费用控制的完整数据与交互边界见 `docs/contracts/SYSTEM_CONTROL_CENTER.md`。系统控制台当前只是已确认的长期模块，不打断 M3 首个内部生产闭环。

## 数据所有权

- PostgreSQL：业务元数据、任务状态、审核状态、权限和审计记录的唯一权威来源。
- 对象存储：视频、音频、字幕原件、处理中间物和导出文件；数据库只保存对象键、哈希和元数据。
- 任务队列：传递任务标识和唤醒信号，不作为业务状态来源。
- Worker：无状态执行者，通过任务租约领取工作并把检查点持久化到 PostgreSQL。
- 浏览器：只持有页面展示状态和短时上传授权，不持有长期云凭据或服务端 API Key。
- 学习事件：PostgreSQL 保存不可变编辑事件及其来源哈希；候选、批准规则和数据集是从事件派生的版本化资产，不允许直接修改原事件。普通业务 API 不提供跨项目学习事件查询。

里程碑 2 将项目业务状态与数据生命周期状态分开保存，避免“上传中”和“已回收”等互不相干的状态被塞入一个枚举。具体状态和接口以 `docs/contracts/M2-upload-lifecycle.md` 为准。

长期工作流中，前置审改与视频字幕验收通过版本化交接连接：前置审改发布待验收修订，验收端只读取该修订的快照并保存自己的轻量修改和冻结结果。局部问题可在验收端修改；整集或批量问题创建返工记录并回到前置审改。任何输入字幕、视频映射或待验收修订变化都会使原冻结签名失效，正式交付只能读取当前有效的冻结验收版本。

公司 SRT、ASR 与采纳稿分别保存并使用内容哈希绑定来源修订。每集可配置对照基准，切换基准只改变差异投影和未确认项的初始建议；已经人工确认的采纳稿必须通过显式操作才能改变。差异对齐使用时间范围、相邻字幕组和去标点规范化文本，最终采纳仍逐条审计为 `company`、`asr`、`merged` 或 `manual`。

基准配置按“系统默认、项目覆盖、单集覆盖”解析；选中集批量切换是一次把覆盖值写入多个单集的显式命令，不创建第四套权威状态。解析后的有效基准可作为只读投影返回，不能独立回写。批量命令必须幂等并返回实际受影响、跳过已确认和失败的集数。

## 失败恢复与付费调用

- 上传通过短时、限对象键、限大小和限时效的授权直传；完成后由后端校验对象与哈希。
- 任务采用显式状态、租约过期和检查点恢复，Worker 退出不能导致任务永久悬挂。
- ASR 等付费调用使用稳定幂等键和供应商请求标识；调用结果未知时进入人工确认或对账状态，不无限重试。
- 整剧 ASR 和画面字识别必须等待项目术语确认门禁，并在任务上固定 `glossary_version_id`；不能静默把旧结果伪装为使用了新术语。
- 术语确认版本不可变；后续修改创建新版本，并把仍引用旧版本的识别结果标记为 `glossary_outdated`，不删除原结果。重跑是显式命令，默认范围为受影响集数，也允许整剧范围。
- 上传与术语整理允许并行推进；识别任务调度同时检查已确认 `glossary_version_id` 和对应视频素材的服务端校验状态，任一条件不足都保持阻塞并返回原因。
- ASR 质量推荐至少综合音频覆盖、术语命中、低置信片段、时间轴完整度和异常长句比例，不能只使用供应商单一置信度，也不能自动替代人工采纳。阈值需通过匿名或获准的真实样本校准后版本化。
- 当前项目内的人工修正可以立即进入项目级提示词和热词建议，但不能自动改写字幕；跨项目聚合只生成候选。候选只有在人工批准、真实回归案例和版本化评估全部通过后才能发布为公司级规则。
- 人工事件长期保留在后台日志库，由持久化优化智能体按管理员选择的模块、时间范围和目标批量分析；单条操作不触发升级。智能体只生成可追溯的规则、提示词、风险词和测试候选，不能直接写生产发布指针。
- 前置审改采用“本地确定性规则优先、可选 AI 快速筛选、人工决定兜底”。本地规则通过固定回归集后可以关闭 AI 或仅做抽样；AI 失败、停用或超预算不能阻断人工主流程。两类建议共用中立投影，任何建议都不能覆盖既有人工决定。
- 人工修改与学习事件使用同一幂等命令身份，未知结果可安全重放；学习归档失败必须进入可恢复状态，不能出现字幕显示已保存但证据永久丢失。规则和数据集版本必须记录来源事件、批准者、回归结果和回退目标。
- 第一阶段学习数据不复制音频或视频，只保存结构化文字、时间范围、模型/术语版本和质量证据。真正的 ASR 微调或蒸馏必须使用另行批准的音频片段数据集和隔离评估集。
- 待验收台词发布执行确定性格式门禁：最终台词去除常规中英文标点，单轴目标 `<=18` 个有效字，`19–28` 字提示优化，`>28` 字阻断；自动断句必须保护姓名、数字和已确认术语，无法可靠切分时进入人工确认。画面字轨不应用该台词格式规则。
- 近期视频字幕验收只执行文件完整性、视频证据和字幕时间轴等技术门禁；复杂内容风险、人物/人脸风险和严重等级模型待真实使用后另行确认，当前不能阻塞主流程。
- 若未来启用复杂风险能力，风险证据、检测覆盖和人工决定必须分别建模；不建设人脸身份库、生物特征模板、跨集人物匹配或跨项目画像。
- 导出与外部提交必须可追踪且防重复执行。
- 正式交付只读取有效冻结验收版本，生成台词 SRT、画面字 SRT 和术语 XLSX；原始视频按“交付后 48 小时 + 7 天回收期”清理，交付产品独立长期归档。

## 仍需用户确认

- 员工邮箱白名单、部署所有者精确邮箱、Access 团队域和两个 Application audience 的部署值；
- 未来是否在外部邮箱身份之上增加应用内组织/项目权限和多租户；
- 生产部署平台、真实对象存储网络实测和扩容参数；
- ASR 供应商、计费上限、超时与重试策略；
- 账号体系启用后的管理员批准、审计记录和备份保留要求；
- 甲方总库接口的认证、目录映射、幂等和失败恢复方式。
- ASR 微调或蒸馏是否允许保存音频片段，以及授权、脱敏、保留期限、训练范围和预算。
