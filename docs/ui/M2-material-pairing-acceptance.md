- 文件夹选择：明确选择一部剧自己的素材文件夹；提示只扫描相对路径、文件名、大小和修改时间，不读取或上传内容。

- 完整页面状态：待处理阻断、全部匹配、扫描中、空文件夹、扫描失败、确认中、确认失败、已确认详情，共 8 类。确认失败提供版本冲突错误码和“读取最新清单”恢复动作。

本节是 `TEST-SRV-20260821-002` 的唯一 UI 验收补充，沿用本文既有 AppShell、素材配对台账、确认弹窗和上传队列，不改变视觉方向，也不制作新原型。

- 上传生命周期：单文件/整批暂停继续、刷新后重选、指纹不符、过期与取消。

### 1. 四阶段唯一流程

1. **未选择**：主按钮为“选择系列文件夹”，次按钮为“选择多个文件”；继续显示服务端已登记事实，例如“已登记 102 个物理文件，共 5.17 GB；等待选择本地原文件”。取消本地选择只清理浏览器草稿，不删除服务端清单、UploadSession、已确认分片或 Asset。
2. **读取元数据**：文件选择完成后的下一帧立即显示“正在读取文件元数据……”及“已读取 N / 102 个文件”。此阶段只读取文件名、相对路径、大小和修改时间，不计算内容摘要、不读取正文或画面，也不上传字节；用户可取消，页面保持可滚动和可响应。
3. **分配预览**：固定显示“已匹配 X / 缺失 Y / 重复 Z / 待人工处理 W”，并区分物理文件数与素材角色绑定数。按“集数｜公司字幕 SRT｜原视频｜画面字幕视频｜问题/操作”核对；必需缺失、重复和未处理项阻断确认，可选画面字幕视频允许明确留空。
4. **确认上传**：只有分配预览无阻断且服务端权威绑定确认成功后，才允许“确认分配并开始上传”。用户看到的一次确认不得被工程实现成假原子操作；清单确认、创建或复用 UploadSession 的先后与失败边界必须等 BACK 合同冻结后映射。上传百分比、确认字节和完成状态只读取服务端事实。

### 2. 目录能力与多文件替代

- 主入口旁显示说明：“系统只读取文件名、相对路径、大小和修改时间，用于分配集数和素材类型；确认前不会开始上传。”
- 运行时检测浏览器目录选择能力。不支持时不得静默隐藏或禁用主入口，必须显示：“当前浏览器不能选择文件夹。请改用‘选择多个文件’，或在支持文件夹选择的浏览器中打开本页。已登记清单不会改变。”
- 原生选择器取消后回焦“选择系列文件夹”，并通过 `aria-live=polite` 提示“未选择任何文件，当前上传清单未改变。”不得自动再次打开选择器。
- 相对路径只用于本地匹配和安全展示；统一处理 `A\B` 与 `A/B`，不展示绝对路径、盘符、对象键或浏览器本地根路径。根目录名称变化不得单独导致已登记素材失配。
- 自动分配可依据既有集数命名规则及文件类型识别公司 SRT、原视频和画面字幕视频。同集同角色只有一个候选时可自动分配；两个以上候选不得猜测，必须展示文件名、相对路径、大小、修改时间并让用户选择。
- 无法识别集数或角色的文件进入“待人工处理”，允许指定合法集数和角色；无关文件可显式排除，不得静默丢弃或误配。同一真实 MP4 若权威清单允许承担两个角色，只显示一个物理文件和一次上传，并标明两个用途。

### 3. 大批量即时反馈与错误明细

- 102 个物理文件、5.17 GB 选择完成后必须立即进入“读取元数据”，不能长时间停留在 0% 且无可见变化。读取计数代表元数据扫描，不得冒充上传进度。
- 全部零匹配时显示“没有文件匹配当前素材清单”，并给出有界计数：路径不符、大小不符、修改时间不符、未识别；不能只显示一句失败。
- 元数据读取失败显示“无法读取文件元数据”及安全摘要，唯一恢复动作是“重新选择系列文件夹”；服务端清单和已有进度继续保留。
- manifest 版本冲突时清除当前提交意图，刷新权威清单，再重新计算本地分配草稿；错误块持焦，禁止用旧映射继续创建上传。
- retryable 或 unknown 不自动重发已发出的写命令，只按 BACK 冻结的稳定身份 GET 查询。确定冲突后刷新权威事实，下一次用户显式确认使用新命令身份；错误仅显示安全原因、下一步和 requestId。

### 4. 单文件与整批暂停/继续

- 单文件与批次分别提供“暂停上传”和“暂停全部上传”。暂停只停止发起新分片，服务端已确认分片、Asset 和绑定不回退；pending 文案为“正在暂停……”，重复点击锁定。
- 暂停完成显示“已上传 {confirmedBytes} / {totalBytes} · 已保留服务端进度”，数值必须来自服务端权威投影。状态严格区分“上传中”“正在暂停……”“已暂停”“等待重新选择”“正在继续……”“会话已过期”“已取消”。
- 同页仍持有正确 File 时，“继续上传/继续全部上传”复用原 UploadSession，只补服务端 `missingParts`，不得重新发送 create 或重复已确认分片；继续 pending 锁定重复操作。
- 页面刷新或重开后固定显示“重新选择原文件后继续”，不得宣称浏览器会自动恢复文件权限。正确原文件通过身份/指纹核对后只补缺失分片。
- 错误文件显示：“文件指纹不符：请选择最初上传的原文件。预期：{相对路径}（{大小}）；本次：{文件名}（{大小}）。”不得创建新会话或覆盖旧文件。
- 会话过期显示：“上传会话已过期，服务端已确认进度不能继续使用。”只有“重建上传并重新选择原文件”可形成新的显式意图；已取消会话保持只读“已取消”，不能恢复为上传中。
- 浏览器本地 File、hashing 或队列计数不能驱动总体百分比；完成只以服务端状态为准。暂停/继续、过期、取消及 unknown 的精确命令和读取字段等待 BACK 合同冻结。

### 5. 焦点、pending 与响应式验收

### A. 总系列文件夹的唯一主流程

1. 主入口“选择总系列文件夹”一次接收整部剧目录；选择完成后必须依次进入“读取元数据 → 三角色分类预览 → 处理缺失/重复/未识别 → 确认 manifest → 开始上传”。不得跳过预览直接上传，也不得把文件选择成功显示成 manifest 已确认。
2. “读取元数据”只读取文件名、相对路径、大小、修改时间和浏览器允许的类型信息。分类预览同时呈现公司字幕、中文识别视频、画面字视频三个角色，并逐集显示自动匹配、缺失、重复、未识别和人工调整结果。
3. 任何必需缺失、同集同角色重复或未处理文件都阻断确认；用户处理完阻断后，确认摘要必须再次显示物理文件数、角色槽数、明确留空数和将开始上传的物理文件数。
4. 确认前上传请求数、已上传字节和新 UploadSession 数必须为 0。只有后端确认 manifest 成功后才进入上传；确认失败或结果未知时保留本地分配草稿，只按稳定身份恢复，不自动上传或重发确认。

### B. 单槽替换

- 每一集的“公司字幕”“中文识别视频”“画面字视频”槽都提供低强调“选择单个文件”动作；动作名称必须包含集数和角色的可访问名称，例如“替换第 12 集公司字幕”。
- 选择成功只重算当前 `集数 + 角色` 槽，并把该文件标为“本地调整未确认”；其他集、其他角色和当前后端 manifest 保持不变。选择器取消、文件类型错误或指纹不符时，原槽与原草稿不变。
- 单槽存在两个以上候选时不得自动取第一个；显示文件名、相对路径、大小和修改时间供用户明确选择。后续再次使用单槽替换时，以最后一次未确认选择覆盖该槽草稿，不创建第二份并行草稿。
- 已有上传或 Asset 不因本地替换被浏览器删除。确认后由服务端决定复用或创建上传身份；前端不能把“已选择替换文件”显示为旧对象已清理。

### C. 三角色独立文件夹与重算优先级

- 总系列入口旁固定提供三个独立入口：“选择公司字幕文件夹”“选择中文识别视频文件夹”“选择画面字视频文件夹”。每次只读取并重算所选角色的整系列草稿，另外两个角色的自动结果、单槽调整和明确留空全部保留。
- 打开角色文件夹选择器前说明“将重新计算全部集的此类型草稿，其他类型不变”；取消选择后回到原入口并播报“未选择文件夹，当前分配未改变”，不得清空该角色或自动再次打开选择器。
- 角色文件夹的新扫描结果替换该角色此前的未确认整系列草稿；随后执行的单槽替换只覆盖对应一格。再次选择总系列文件夹时重新计算三角色草稿，但仍不修改已确认 manifest，直到用户完成同一确认门。
- 浏览器不支持目录选择时，四个文件夹入口均保留可见说明并提供同角色“选择多个文件”替代；替代入口必须遵守相同重算范围，不能把三类文件混入错误角色。

### D. 计数、状态与变化场景验收

- 摘要同时显示“物理文件 N 个 / 角色槽 M 个”；一个真实 MP4 同时承担中文识别视频和画面字视频时计为 1 个物理文件、2 个角色槽，只创建或复用 1 个上传身份，并在两个槽位标记“共享同一文件”。
- 正式变化场景必须覆盖：总系列四阶段；三个角色文件夹分别重算且另外两类不变；三种角色逐集单槽替换；选择器取消；目录能力不支持；0/部分/全部匹配；重复、必需缺失、可选留空、未识别、类型错误和共享 MP4；确认 pending/失败/unknown；上传暂停、继续、刷新重选、指纹不符、过期和取消。
- 文件夹读取期间由入口相邻状态容器持有 `aria-busy` 并播报已读取数量，不抢走原入口焦点；处理完成后，有阻断聚焦唯一问题摘要，无阻断聚焦分配结果标题。确认 pending 沿用活动 Modal 焦点闭环与关闭锁；单槽/角色重算失败聚焦对应局部 ErrorBlock，不把焦点送到页面顶部或 `BODY`。
- `1024×768` 保留四个入口的清晰分组，台账只在自身容器横滚；`390×844` 将总系列入口、三个角色入口和摘要单列，单槽主动作无需横向滚动即可到达，触控目标至少 44px、输入字号至少 16px。两视口都不得因长文件名、相对路径或错误文本产生根页面横向溢出。
- 本 Rev 只冻结交互、状态与验收门；精确 manifest、UploadSession、版本冲突和清理语义继续由 BACK 契约提供，生产前端不得据本文自造接口或第二状态源。

### Rev1 固化结论

本节 A–D 是本租约中素材选择、角色重算、共享上传与变化场景的唯一可实现/验收解释；如与本文较早的素材选择描述冲突，以本节为准，且仍不授权生产接口或第二状态源。
