## 1. 范围与责任

Wave B 只回答两个问题：员工从项目中心选择哪些剧发起中文识别，以及刷新后到哪里恢复一批跨项目意图。选择单位是 `Project`，不是上传文件、上传会话、素材槽位或单集。

项目中心保存浏览器选中状态，但资格、总数、排序和分页来自服务端；`ASRDispatchGroup`、逐项目 accepted/blocked、子批次、取消意图和刷新恢复来自 PostgreSQL。浏览器不得重新推导门禁、补造批次或把局部接受显示为整批成功。

员工页面不展示供应商、模型内部代码、并发、预算、服务器、密钥、精确金额或管理员入口。“中文识别任务”是 ASR 专用恢复视图，不是上传任务或通用任务中心。

## 3. 项目中心多剧选择

### 3.1 列表与服务端查询

工具栏按“项目搜索 / 中文识别资格 / 项目状态 / 更新时间排序”排列。资格筛选为：全部、可识别、缺术语、缺视频、识别中、失败。搜索、资格、排序、总数和分页都由服务端返回；页面不得在当前页内二次筛选后伪装成完整结果。

紧凑表格最小宽度约 `1080px`，列为：选择、项目、素材、术语版本、中文识别资格、最近任务、更新时间、操作。默认排序先突出失败与可处理项目，再按更新时间倒序；已有运行项目仍可打开，但不能作为新的可创建项目冒充通过。

### 3.2 选择层级

| 状态 | 页面表现 | 行为 |
| --- | --- | --- |
| 未选择 | 普通搜索筛选工具栏 | 不显示批量按钮 |
| 逐行选择 | 批量栏显示已选、可创建、阻断 | 阻断项目保留在选择中 |
| 当前页全选 | 表头复选框为全选或混合态 | 只选择当前页真实项目 |
| 跨页全选 | 显式提示“选择全部 N 部符合当前条件的项目” | 后端条件与选中总数持续可见 |
| 达到 20 部 | 文本提示已达单次上限 | 已选保留，其他复选框禁用，不静默截断 |
| 搜索、资格、项目状态改变 | 清除跨页全选并播报具体变化来源 | 这些查询改变服务端成员集合，不能携带隐藏的旧项目 |
| 纯排序、翻页 | 保留跨页全选并播报仍选择 N 部 | 只改变同一权威集合的观察顺序 |

选中后批量栏替换普通工具栏，固定显示“已选择 N 部 / 可创建 N 部 / 阻断 N 部”，次级动作为“清除选择”，唯一主操作为“批量中文识别”。

## 4. 批量确认侧栏

侧栏约 640px，首屏固定六项摘要：已选、可创建、阻断、总集数、预计新任务、可复用结果。逐项目表最小宽度约 760px，仅在侧栏内部横滚，列为项目、术语/热词、视频覆盖、集数、新建/复用、资格或返回结果。

局部阻断时，提交文案必须是“只为 N 部可执行项目创建”，并在按钮上方说明阻断项目不会创建、仍保留在结果中。每个阻断项目只有一个上游修复入口：缺术语回“术语”，缺视频回“概览与素材”，项目不可编辑回项目状态说明。

提交前的 `canCreate` 是服务端资格预检；提交后的 `accepted/blocked` 是本次 Dispatch 的权威返回。两者不得混写：资格可能在提交时变化，返回结果必须逐项目覆盖预检并给出稳定原因。

| 提交阶段 | 可见事实 | 焦点与恢复 |
| --- | --- | --- |
| 打开 | 六项摘要、全部所选项目、阻断原因 | 焦点进入关闭按钮，关闭恢复批量主操作 |
| 提交中 | 同一项目集合、稳定意图、请求只发送一次 | 侧栏容器获得编程焦点；所有按钮禁用，Tab 双向留在容器，Escape、遮罩、关闭和重复激活受阻 |
| 全部接受 | accepted 数与子批次入口 | 关闭侧栏，聚焦 `role=status` |
| 部分接受 | 已接受和已阻断分别计数 | 不显示“全部成功”；阻断行保留唯一修复入口 |
| 未知结果 | 同一意图、规范化项目集合、请求标识、重新读取 | 不生成第二个创建请求；重新读取同一 Dispatch，安全取消获得焦点 |
| 确定失败 | 同一意图、规范化项目集合、稳定原因和请求标识 | 侧栏保留，恢复安全取消焦点；显式修正后才按同一意图重试 |
| 读取失败 | 已知接受结果与错误并存 | 不抹掉已创建子批次，只提供重新读取 |

提交成功是进入结果侧栏的唯一条件。原型以 `intent_dispatch_026` 演示：pending 时创建请求计数保持 1；未知结果的“重新读取”明确显示“创建请求仍为 1 次”，不会以刷新名义重发创建。

## 5. 员工侧“中文识别任务”

### 5.1 列表

全局侧栏“作业”分组只增加“中文识别任务”。页面固定顺序为搜索筛选、任务表、分页；不重复页面大标题，不显示管理员入口。

任务表最小宽度约 `1120px`，列为：派发、项目、接受结果、状态、项目进度、质量与用量、更新时间、操作。默认排序为“需对账 / 失败 / 取消请求 / 运行与排队 / 其他”，同组按更新时间倒序。搜索、状态、排序和分页为服务端查询。

每行只有一个直接动作“查看任务”。接受结果使用“已选 6 / 接受 4 / 阻断 2”；项目进度使用“2 / 4 部已完成”，不能混成“2 / 6”。质量与用量只显示“通过 42 集、警告 3 集、用量已记录”或“用量待对账”。

### 5.2 Dispatch 与项目状态

| 状态 | 中文与非颜色编码 | 列表事实 | 唯一下一动作 |
| --- | --- | --- | --- |
| `queued` | 靛蓝空心圆 + 排队中 | 已接受，等待项目公平推进 | 查看任务 |
| `running` | 靛蓝圆点 + 识别中 | 至少一个项目子批次运行 | 查看任务 |
| `partial` | 琥珀方形 + 部分完成 | 同时有可用结果和失败、取消或需对账 | 查看任务 |
| `completed` | 绿色圆点 + 已完成 | 全部已接受项目有可用或复用结果 | 查看任务 |
| `failed` | 红色圆点 + 失败 | 已接受项目没有可用结果且失败已确定 | 查看任务 |
| `cancel_requested` | 灰色圆点 + 取消请求中 | 取消意图已持久化，仍等待子批次终态 | 查看任务 |
| `reconciliation_required` | 红色菱形 + 需对账 | 结果或处理用量未知，自动重试暂停 | 查看任务 |
| `cancelled` | 灰色圆点 + 已取消 | 未完成项目已确认停止，既有结果保留 | 查看任务 |

“部分接受”是创建结果，不替代运行状态。一个 Dispatch 可以同时显示“接受 4 / 阻断 2”和“4 部中 2 部已完成”。

### 5.3 任务详情与恢复

详情侧栏顶部显示派发编号、创建时间、已选/接受/阻断、请求标识和最后刷新时间。逐项目表显示项目、集数、新建/复用、子批次状态、质量与处理用量、唯一动作。失败、取消和需对账分别计数，不能共用一条模糊“异常”文案。

`DSP-0814-026` 的不可变示例事实固定为：accepted 仅匿名项目甲、丙、丁，blocked 包含匿名项目乙；accepted 合计 `92 集 / 88 新建 / 4 复用`，详情已形成或复用 `46 / 92`。列表、部分接受结果与详情不得出现 83 集，也不得把被阻断的乙写入逐项目子批次。

- 部分接受：已接受项目直接进入子批次；阻断项目保持具体原因和唯一上游修复入口。
- 失败：全局页只提供进入项目级批次，不复制“仅重试失败集”。
- 取消：当前示例明确只影响匿名项目丙这 1 个仍在运行的子批次；匿名项目甲已完成结果、匿名项目丁需对账事实、已形成结果和历史用量全部保留。确认框打开后聚焦“暂不取消”；提交中容器获焦、双按钮禁用、Tab 不离开，Escape、遮罩和重复激活受阻。确定失败保留同一取消意图并恢复安全焦点；成功只表示取消意图已保存，丙进入“取消请求中”，随后聚焦页面 `role=status`。
- 需对账：显示结果或用量未知、自动恢复暂停和请求标识，不显示普通重试。
- 刷新恢复：读取中保留既有行；失败显示原因、请求标识和唯一“重新读取”；成功用 `role=status` 播报并更新权威投影。

## 6. 空错加载与禁用

| 场景 | 必须表现 |
| --- | --- |
| 项目列表加载 | 表格骨架和 `aria-busy=true`，不表现为空 |
| 无符合项目 | 当前服务端筛选摘要、清除筛选，不显示批量栏 |
| 资格读取失败 | 保留项目基本信息，禁用选择，显示请求标识和重新读取 |
| 任务列表加载 | 表格骨架和上次刷新语境 |
| 无 Dispatch | 解释应从项目中心选择多部剧，不提供上传或新建文件入口 |
| Dispatch 读取失败 | 保留已知接受/子批次事实，唯一“重新读取” |
| 项目不可编辑 | 文字+禁用态+原因；不能只用灰色 |

## 7. 键盘、反馈与响应式

- 所有复选框有项目名称或范围的可访问名称；跨页全选升级用按钮，不依赖仅视觉提示。
- 状态标签包含中文文字、形状和语义色；项目进度同时显示数字，不只显示条宽。
- 侧栏和确认框打开后焦点进入，`Tab / Shift+Tab` 双向闭环；非提交期 `Escape`、遮罩、关闭或取消可退出并恢复触发项。提交中焦点留在容器，按钮禁用且只发送一次。
- `1440×900`：侧栏 204px，项目表和任务表当前宽度足够时不横滚；确认/详情侧栏不推动根页面。
- `1024×768`：分别验收侧栏 204px 与 72px。根页面 `scrollWidth === clientWidth` 或水平可滚范围为 0；Windows 非覆盖式纵向滚动条约 10px 槽位不算横溢。项目表、任务表和面板内表只在自身容器横滚。
