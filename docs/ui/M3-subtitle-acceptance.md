## 5. 视口与焦点验收

| 视口 | AppShell | 生产工作台要求 |

| `1440×900` | 展开 `204px` | 主内容约 `1236px`；左 `220` / 中约 `690` / 右 `326`，播放器与时间轴默认 `54% / 46%`，保存反馈首屏可达 |

仓库外 Rev 4 方案 A 证据未包含生产 AppShell 侧栏，因此只验证方向与本轮入口：`1440×900` 实测三栏 `220/894/326`、播放器/时间轴 `410/349`；`1024×768` 实测 `182/572/270`、播放器/时间轴 `339/288`，两者页面根宽均等于视口。1024 右栏 `clientWidth=scrollWidth=269`，时间轴 `clientWidth/scrollWidth=572/603`，横滚只留在时间轴自身。生产前端必须在真实 AppShell 中按上表重新测量，不能把证据原型的中央宽度硬编码为 CSS 常量。低于当前电脑屏幕承诺且中央无法保持工作宽度时，右栏改为由明确按钮打开的覆盖抽屉，不能静默隐藏字幕编辑或问题处理。

- 所有按钮、页签、剧集、Cue、轨道块、表单和抽屉有可见焦点。
- 对话框/抽屉 Tab 与 Shift+Tab 闭环；非提交时 Escape 关闭，焦点回触发点。
- 错误出现时若已有活动 `aria-modal=true`，不得把焦点抢到背景错误块。
- 保存/通过再次失败时焦点回唯一恢复按钮；成功后回原编辑上下文或下一集标题。
