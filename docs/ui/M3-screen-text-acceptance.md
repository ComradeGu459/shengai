## 3. 页面结构验收

### 3.1 页首与唯一主动作

页首固定显示当前术语版本、画面字视频覆盖、当前批次和发布门禁。没有可审核批次时，唯一主操作是“新建识别批次”；存在草稿时，页面级主操作转为发布。批次运行摘要只展示权威范围、已处理集数、失败/需对账数量和处理帧数，不展示供应商、模型、密钥、金额、并发或浏览器估算进度。

新建确认覆盖“整剧 / 选中集 / 单集”，同时显示固定术语版本、目标视频覆盖和阻断集。门禁失败时不静默跳过目标集，不产生部分未知范围。

### 3.2 三栏工作区

| 区域 | 固定职责 | 不承载 |
| --- | --- | --- |
| 集/批次队列 | 集状态、待处理数量、失败/需对账、批次历史 | OCR 文本编辑、全局任务 |
| 候选表 | 搜索、筛选、排序、选择、候选状态与定位 | 视频播放器、任意时间轴 |
| 证据/编辑 | 当前候选截图、视频时间、文字、分类、位置、时间、术语回执和决定 | 其他候选的批量状态 |

候选表默认人名条优先，同类按首次出现排序。表格固定列为“选择 / 文字与分类 / 时间 / 位置 / 术语证据 / 状态 / 操作”；宽度不足时仅表格容器横向滚动，不推动根页面。

证据区显示当前候选同源截图、前后 2 秒、跳回候选、分辨率、置信度和来源。放大层按媒体元数据使用 `object-fit: contain`，竖屏、横屏或方形不裁切。术语回执明确“命中术语 Vn / 身份是否由已确认术语提供”，不把 OCR 文本自动升级为人物身份。

## 4. 状态矩阵

### 4.1 逐集状态

| 契约状态 | 员工文案 | 直接动作 | 约束 |
| --- | --- | --- | --- |
| `not_started` | 未开始 | 进入新建批次 | 无活动任务 |
| `queued` | 排队中 | 查看 | 不伪造进度 |
| `running` | 识别中 | 查看 / 批次取消 | 仅权威处理帧数 |
| `review_pending` | 待审核 | 审核候选 | 未完成前阻断发布 |
| `completed` | 已完成 | 查看 | 决定和候选可回查 |
| `confirmed_empty` | 明确空集 | 查看 / 重新识别 | 必须由员工显式确认 |
| `failed` | 失败 | 重新识别本集 | 显示原因和请求标识 |
| `cancel_requested` | 取消请求中 | 查看 | 不立即伪装已取消 |
| `cancelled` | 已取消 | 查看历史 | 保留已完成事实和用量 |
| `reconciliation_required` | 需对账 | 查看对账说明 | 无普通重试 |
| `stale` | 来源已变化 | 从最新来源新建 | 旧草稿只读 |

所有状态同时使用中文文字、语义色和稳定形状，不以颜色单独编码。

### 4.2 候选状态与决定

| 状态 | 员工文案 | 允许动作 | 保留事实 |
| --- | --- | --- | --- |
| `pending` | 待确认 | 保留、忽略、编辑、拆分 | 原始 OCR、证据、系统建议 |
| `approved` | 已保留 | 查看、编辑 | 原始 OCR 与决定事件 |
| `edited` | 已修改 | 查看、继续编辑 | 原值、修订值与审计事件 |
| `rejected` | 已忽略 | 恢复 | 原始 OCR、证据和忽略事件 |

系统建议与人工决定分列表达；置信度或术语命中不能自动替代人工决定。

### 4.3 页面与异步状态

- 加载：保留页面骨架和区域身份，不显示“空”。
- 无批次：说明前置门禁并只提供“新建识别批次”。
- 明确空集：必须经过确认框；零候选本身不是完成。
- 读取失败/再次失败：保留已成功集，显示原因、请求标识和唯一“重新读取候选”。
- 提交中：活动弹窗容器获焦，关闭、取消和确认禁用，`Escape`/遮罩/重复激活不产生第二个请求。
- 确定失败：保留原输入与同一意图，焦点回安全操作。
- 未知结果：保留同一请求标识，只允许重新读取，不自动再次创建。
- 来源失效：旧候选和人工决定只读，唯一下一步是从最新来源新建批次。
- 项目不可编辑：禁用创建、决定、重试、取消和发布，保留只读查看。

## 5. 关键交互验收

### 5.1 选择与批量决定

未选择时不显示批量栏。选择当前页候选后，普通工具栏切换为“已选择 N 项 / 选择全部 N 项待确认候选 / 批量忽略 / 批量保留”。显式跨页选择只包含当前服务端筛选范围内的 `pending` 候选；搜索、状态或分类改变成员集合时清除跨页选择并播报，纯排序/翻页保持同一权威集合。局部失败留在原行并显示唯一重试入口，不显示整批成功。

### 5.2 高频决定与编辑

当前候选的唯一主决定为“保留并下一条”，次级动作是忽略、拆分左右。忽略后直接提供恢复。文字、分类、位置、开始/结束时间保存为 `edited` 审计事件，不覆盖原始识别值；时间必须满足开始小于结束且不超过视频时长。

### 5.3 左右拆分、人名条与人工新增

左右拆分确认框显示两条独立文本、共同来源时间和左右位置，提交后生成两个独立 Cue。人名条只能引用已确认术语或标为身份待核对。人工新增必须填写文本、分类、位置和时间，并绑定当前视频时间或截图证据；首版不提供任意时间轴编辑器。

### 5.4 空集、失败重试、取消与需对账

- 空集：确认框说明决定可审计且以后可重新识别。
- 失败重试：只重试失败或明确空集目标，保留其他集候选、人工决定和用量；失败例显示 `REQ-ST-06-018` 和唯一提交。
- 取消：只影响非终态集；已完成、已决定和已记录用量不删除。
- 需对账：解释结果或用量未知，显示请求标识与对账说明，不提供普通重试。

### 5.5 发布门禁

发布必须同时满足：全部目标集为已完成或明确空集；没有待确认、失败、需对账或活动任务；文字非空；时间合法且在视频时长内；左右拆分为独立 Cue；人名条身份有术语或证据；同一身份写法一致。门禁失败必须列出具体集/候选并提供定位。成功形成不可变 `ScreenTextRelease`、Cue 和 UTF-8 BOM 画面字 SRT；历史版本只读下载。

## 6. 键盘与焦点

- 所有弹窗打开后焦点进入安全关闭/取消；表单弹窗的 `Tab / Shift+Tab` 顺序覆盖输入、单选、选择和按钮。
- 非提交期 `Escape`、取消和遮罩关闭并恢复本次原始触发项。
- 提交中关闭、取消和确认均禁用，焦点留在弹窗可编程容器；成功聚焦 `role=status`，失败保留弹窗和输入。
- 证据放大层打开后聚焦关闭；`Tab / Shift+Tab` 留在放大层，关闭后回原“放大”。
- 真实 DOM 定向复验：失败重试弹窗共有 3 个可操作按钮；从末项按 `Tab` 回到“关闭”，从首项按 `Shift+Tab` 回到“重新识别第 06 集”，两次 `dialog.contains(activeElement)=true`；`Escape` 关闭后焦点恢复到“第 06 集”原触发项。

## 17. SCREEN-TEXT-REVIEW-UI-1747 最小审改交互冻结

### 17.1 范围与唯一状态源

- 本节只收敛现有画面字员工审改工作台的选择、证据联动、高频决定、批量范围和双视口；继续使用同一 `AppShell`、三栏工作区、`ScreenTextWorkspace`、候选四态与决定事件，不重画全站、不新建控制面。

### 17.2 行选择与证据联动

| 场景 | 必须成立 | 禁止 |
| --- | --- | --- |
| 选择候选行 | 中表高亮行、右栏代表截图、视频定位时间、文字/分类/位置/起止时间引用同一 `candidateId + revision` | 行 A 高亮但显示行 B 证据 |
| 切换候选 | 先锁定写入并读取新证据；成功后再开放新候选合法动作 | 读取期间保留旧截图并允许决定 |
| 决定成功 | 服务端确认后才更新四态；“保留”可自动选择下一条 `pending`，并同步更新整套证据 | pending/失败时提前跳到下一条 |
| 1024 证据下移 | 下移后继续绑定同一当前行，处理动作后的焦点顺序可达证据区 | 把下移证据变成第二份选择或独立草稿 |

候选 ID、批次 ID、修订号、provider/adapter/model/deployment 不占主工作面；requestId 仅在错误恢复或详情中出现。员工主界面以集数、候选文字、时间、位置、状态和证据说明为主。

### 17.3 高频决定文案与事件不变量

- `pending` 普通候选的主决定文案为“保留”，次决定为“忽略”。“保留”仍产生既有 `approved` 事件；“忽略”旁固定说明“本条不纳入画面字字幕，可从‘已忽略’恢复”，仍产生既有 `rejected` 事件。
- `rejected` 的唯一决定动作是“恢复为待确认”，沿用既有恢复事件；`approved / edited` 不因本轮新增撤销状态或客户端回退。未拆分左右父候选继续只允许忽略或拆分，不出现保留。
- 所有决定 pending 时保持当前行与证据、锁重复提交；确定失败保留原行和同一证据并聚焦错误，unknown 只恢复同一稳定意图。服务端成功后才更新状态和自动前进。

### 17.4 证据不可用与唯一恢复

- 代表截图不可用、摘要不一致或正在重读时，统一锁定行/跨页选择、保留、忽略、恢复、编辑、保存、拆分、人工新增和全部批量写入；视频可播放也不能绕过截图门禁。
- 错误区显示安全原因、requestId 和恰好一个“重新读取候选证据”。重读 pending 时入口不可重复激活；再次失败焦点回唯一重读；恢复成功焦点进入“候选证据与编辑”容器，随后才恢复当前候选允许的动作。

### 17.5 批量显式范围

- 普通勾选只作用当前页，批量栏持续显示“当前页已选 N 项”；只有用户点击“选择全部 N 项待确认候选”后，范围才升级为当前服务端筛选集合。搜索、状态或分类改变成员集合时清除跨页选择并播报，排序/翻页只改变观察顺序。
- 批量保留/忽略只提交显式范围内仍为 `pending` 且修订匹配的候选；`approved / edited / rejected`、未拆分左右父候选和已失效候选均不被浏览器补入。部分成功逐项显示结果，失败项保留原状态和唯一重试，不用整批成功覆盖。

### 17.6 1440 / 1024 验收门

- `1440×900` 保持“集/批次队列—紧凑候选表—证据/编辑”三栏同屏；当前行、代表截图和视频时间必须可同时核对。
- `1024×768` 覆盖 204px 展开与 72px 收起侧栏；证据栏按既有规则下移到表格之后，根页面无横向溢出，候选表只在自身容器横滚。布局变化不能改变当前行、批量范围或决定资格。
- 定向实现验收至少覆盖：键盘选择两条候选的证据同步；保留成功自动前进与失败不前进；忽略说明及恢复；截图 `503 → 503 → 200` 全程写锁与焦点；当前页/显式跨页批量；1440/1024 同一选择投影。不得用源码字符串检查代替行为验证。

本 UI 切片不修改生产 React、backend、contracts、迁移或既有四态/决定事件，不启动真实 OCR，不建立第二状态源。后续只需 FRONT 按本节做最小映射与定向测试；若实现需要新增候选状态、合同字段或控制面，必须停止并交规划。
