# M3 项目工作台 / 中文识别 UI 设计与验收

状态：`UI-M3-02 Rev 2` Wave A 增量设计已完成，现交规划总线审核；Rev 1 页面结构与 12 张证据冻结。本文只定义项目内中文识别批次页，不代表生产 React 或后端已经实现。

权威输入：`DESIGN.md`、`docs/contracts/M3-asr-batch.md`、`docs/contracts/MODULE_RESPONSIBILITY_MATRIX.md` 中文识别行、`docs/contracts/LOCAL_APP_PARITY.md`“公司稿与 ASR 对照 / 运行与任务恢复”行。

## 1. 范围判读

本页帮助负责一部剧的员工完成四件事：确认术语版本和视频 Asset 双门禁、创建整剧/选中集/单集批次、查看批次与逐集事实、处理取消/失败集重试/需对账。它不是上传页，也不是全局任务中心；不显示字幕正文、播放器、OCR、供应商密钥、账号、模型参数或真实付费调用。

依据职责矩阵，本页的唯一权威数据是 PostgreSQL 中的 `ASRBatch / ASRJob / ASRAttempt / ASRResult / Usage` 投影。浏览器只保存筛选、选中集、展开批次、面板开合和未提交表单，不根据倒计时或本地百分比猜测业务完成。

## 2. Impeccable 审计与减法

### 2.1 必须保留

- 顶部持续可见的双门禁、固定术语版本、视频覆盖和“模拟识别”标识。
- 唯一页面级主操作“新建模拟识别批次”。
- 一张行动优先的批次表和一个原位展开的逐集工作区。
- 运行状态与质量状态分开；状态同时使用中文文字、语义色和形状标记。
- 取消、仅重试失败集、需对账和旧术语版本过期的明确边界。
- 请求标识、尝试、质量、处理用量与热词证据可回查，但不挤占主表；精确费用留在系统控制台。

### 2.2 已删除或收纳

- 不使用总量大卡片、环形进度、模型配置墙或“AI 能力”宣传区。
- 不在项目上下文显示尚未启用的画面字、前置审改、字幕验收或交付入口。
- 字幕正文、逐轴证据、播放器和公司稿/ASR 采纳全部留给后续前置审改。
- 供应商、模型、密钥、并发与预算不在员工页面提供编辑入口。
- 逐集尝试、诊断和质量指标进入侧栏；低频批次历史不使用整页弹窗。

## 3. 正式页面结构

1. 统一 `AppShell`：204px 可收起至 72px 的侧栏、64px 顶栏，标题只出现一次。
2. 项目上下文条：返回项目中心、匿名项目身份、项目状态，以及“概览与素材 / 术语 / 中文识别”。
3. 双门禁摘要：术语 Vn、已校验视频覆盖、模拟适配器，以及唯一“新建模拟识别批次”。
4. 模拟说明：明确零外部网络、仅作链路验证、非真实准确率验收。
5. 批次工具栏：批次编号搜索、状态筛选、行动优先/更新时间排序、刷新状态。
6. 紧凑批次表：批次、范围、模式、状态、集数进度、质量、处理用量、更新时间、唯一“查看批次”。
7. 原位批次详情：不可变输入、热词回执、请求标识、结果修订、总体进度、质量/用量摘要和逐集表。
8. 右侧受控面板：新建批次、查看质量/尝试/对账说明或查看本批次热词证据；关闭后恢复原触发项。
9. 居中确认框：创建、取消、仅重试失败集三类高影响命令。

## 5. 批次状态矩阵

| 后端状态 | 中文与非颜色编码 | 列表事实 | 唯一下一动作 |
| --- | --- | --- | --- |
| `blocked` | 红色圆点 + 已阻断 | 一个或多个请求集未满足双门禁，批次未执行 | 查看阻断集并返回概览与素材或术语 |
| `queued` | 靛蓝空心圆 + 排队中 | 已持久化，等待 Worker；不显示浏览器假进度 | 查看批次；必要时取消 |
| `running` | 靛蓝圆点 + 识别中 | 至少一集运行，显示已形成/复用结果数 | 查看批次；可取消；失败集存在时可重试 |
| `partial` | 琥珀方形 + 部分完成 | 同时存在可用结果与失败/取消/需对账 | 仅重试明确失败集；需对账不混入重试 |
| `completed` | 绿色圆点 + 已完成 | 全部请求集有可用或明确复用结果 | 查看结果与质量摘要 |
| `failed` | 红色圆点 + 失败 | 没有可用结果且已确定失败 | 仅重试失败集 |
| `cancel_requested` | 灰色圆点 + 取消请求中 | 取消意图已持久化，仍有执行中或待后端确认的逐集任务 | 查看批次并等待权威终态；不得显示已取消 |
| `reconciliation_required` | 红色菱形 + 需对账 | 全部请求集结果或处理用量仍存在未知事实，暂停自动恢复 | 查看对账说明；不显示普通重试 |
| `cancelled` | 灰色圆点 + 已取消 | 未完成项均确认停止且无未知外部结果 | 只读查看历史，不删除结果 |

页面状态另覆盖：加载骨架、无批次、批次读取失败、项目不可编辑。加载不得表现为空；读取失败保留已完成结果不会丢失的说明、请求标识和唯一“重新读取”。

## 6. 逐集运行与质量状态矩阵

| 逐集运行状态 | 中文表现 | 质量列 | 行级动作 |
| --- | --- | --- | --- |
| `queued` | 排队中 | 尚未形成 | 查看尝试 |
| `leased` | 准备中 | 尚未形成 | 查看尝试；不暴露租约内部值 |
| `running` | 识别中 | 尚未形成 | 查看尝试 |
| `completed` + `pass` | 已完成 | 质量通过 | 查看质量 |
| `completed` + `warning` | 已完成 | 质量警告 | 查看质量；结果仍可用 |
| `completed` + `rejected` | 已完成 | 结果不可用 | 查看质量原因；此前更好结果继续可用 |
| `failed` | 失败 | 无可用结果或保留旧结果 | 查看原因；重试只从批次级发起 |
| `cancel_requested` | 取消请求中 | 保留已形成质量 | 查看尝试；不能显示已取消 |
| `cancelled` | 已取消 | 未形成或保留旧结果 | 只读查看历史 |
| `reconciliation_required` | 红色菱形 + 需对账 | 结果或处理用量未知 | 查看对账说明；禁止普通重试 |

质量侧栏至少可容纳音频覆盖、空结果、Cue 数量与公司稿差异、异常长段、时间轴异常、术语命中、低置信片段和幻觉信号。质量侧栏不显示或编辑字幕正文，不播放视频，也不把置信度直接翻译成“字幕可用”。

## 7. 取消、失败重试、对账与版本

- 取消确认必须说明：未开始集终止；已经执行的集可能先进入取消请求或需对账；已完成结果和用量保留。提交成功只表示取消意图已持久化，页面随后继续读取后端状态。
- “仅重试失败集”只包含明确 `failed` 集，并列出集数。成功、警告、复用、取消和需对账均不重复；重试创建新尝试，原失败原因和此前成功结果保留。
- 需对账同时展示“结果或处理用量未知”“自动重试已暂停”和请求/诊断标识。当前无真实供应商，不提供虚构的对账完成命令。
- 员工页只显示处理时长、任务数、质量摘要和用量“已记录 / 待对账”，不显示每次请求精确金额；精确费用归入独立系统控制台。本页只写边界，不提供控制台入口。
- 旧批次继续显示实际术语 Vn，并以文字标记“术语版本已过期”。新术语版本只影响新批次或显式重跑，不改写旧结果。

## 8. Rev 2 热词证据与应用回执

Rev 1 的 AppShell、双门禁、创建范围、批次表、逐集工作区、取消/重试/对账流程和 `evidence/01–12` 全部冻结。Rev 2 只在批次详情增加低频“本批次热词”入口，不给主表增加新常驻列。

### 8.1 同项目权威热词证据

- 侧栏顶部固定展示当前批次的同项目不可变术语版本、热词投影版本、稳定摘要，以及实际纳入、规则过滤和适配器截断数量。
- “已纳入热词示例”和“过滤与截断证据”渐进展开；过滤说明具体原因，截断说明由适配器能力产生并按稳定顺序记录。
- 页面不得读取草稿、其他项目术语或跨项目汇总，不暴露完整普通员工日志。摘要用于核对批次身份，不作为浏览器侧业务决策源。

### 8.2 五类回执

| 回执 | 员工中文 | 必须显示的事实 | 禁止误导 |
| --- | --- | --- | --- |
| `simulated` | 模拟已应用 | 模拟管线已读取本批次热词 | 只证明链路，不证明真实准确率 |
| `submitted` | 已提交 | 请求携带热词且服务已接受 | 已发送不等于准确率已提升 |
| `partially_submitted` | 部分提交 | 已发送/省略数量与省略原因 | 不得简化为全部已提交 |
| `unsupported` | 不支持热词 | 识别可能继续，但本次没有应用热词 | 必须明确警告，不能显示成功 |
| `unknown` | 回执未知 | 没有可确认回执；必要时进入需对账 | 不得猜测提交成功 |

所有回执使用“中文文字 + 语义色/形状 + 稳定代码”三重编码。只要没有同样本 A/B 证据，摘要统一为“热词链路已接通，准确率未验证”，并持续显示“已发送不等于准确率已提升”。

### 8.3 焦点与响应式

- “本批次热词”是详情次级动作；打开后焦点进入关闭按钮，`Tab / Shift+Tab` 在侧栏闭环，`Escape`、关闭或遮罩退出并恢复原触发按钮。
- 1440 下侧栏约 540px；1024 侧栏展开/收起两态仍不推动根页面。内容过长只在侧栏自身纵向滚动，批次与逐集表的横滚归属不变。

## 9. 键盘、反馈与非颜色编码

- 所有抽屉和确认框都有可访问名称；打开后焦点进入语境，Tab/Shift+Tab 双向闭环，非提交期 Escape、取消、关闭或遮罩可退出并恢复原触发项。
- 提交中焦点留在 dialog 容器，按钮禁用且命令只发送一次；失败保留输入和错误，焦点回到安全操作；成功聚焦现有 `role=status`。
- 状态标签均包含中文文字、形状标记和语义色；进度同时显示数字文本，不只用进度条宽度。
- 输入、按钮、链接和表格操作有统一焦点环；可点击批次编号保留下划线反馈和按钮语义。
- 错误文案必须同时显示原因、请求标识和唯一恢复动作；局部失败不得覆盖其他集的成功结果。

## 10. 1440 / 1024 布局与滚动归属

### 1440×900

- 侧栏 204px，顶栏 64px；双门禁摘要保持单行，唯一主操作在右侧。
- 批次表约 `1120px` 最小宽度，逐集表约 `1080px` 最小宽度；当前宽度足够时不产生横滚。
- 批次详情在主表下原位展开，右侧面板宽约 `540px`，不推动根页面。

### 1024×768

- 必须分别验收侧栏 204px 展开和 72px 收起。项目上下文条折为两行，门禁摘要折为两列，唯一主操作另起一行。
- 根页面 `scrollWidth === clientWidth` 或水平可滚范围为 0；Windows 非覆盖式纵向滚动条造成的约 10px `innerWidth/clientWidth` 差异不算横溢。
- 批次表和逐集表分别只在自己的 `.tableWrap` 内横向滚动；两个容器互不借用根页面滚动。
- 新建/质量侧栏和确认框只在自身纵向滚动，焦点和主操作保持可达。
