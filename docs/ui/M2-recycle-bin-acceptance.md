## 关键交互结论

### 项目中心回收

- 行级动作固定命名为“移入回收站”，不使用“删除”。
- 确认框显示项目名称，并把影响拆成三条可扫描事实：立即终止未完成上传；48 小时内可恢复且保留已完成 Asset/清单/资料；到期进入后台清理后不可恢复。
- 示例确认后显示：“项目‘雾港来信’已移入回收站，48 小时内可以恢复；2 个未完成上传已终止。”
- 正式前端必须等待后端成功响应再移动项目；原型中的本地切换只用于展示目标反馈，不构成业务状态实现。

### 回收站列表

- 默认按“恢复窗口最短优先”，支持项目名称、回收时间排序和生命周期筛选。
- `已回收` 同时显示剩余时间与明确截止时间，唯一主操作为“恢复项目”。
- `清理中` 和 `等待后台重试` 都不可恢复，不提供立即永久删除、强制恢复或手动立即清理。
- 恢复成功明确说明已完成 Asset/清单保留，但此前终止的未完成上传不会自动复活；恢复失败保留项目并允许再次恢复。
- `purged` 不保留在普通列表，只在列表刷新时短暂显示“项目已清理”结果，随后从列表消失。

## 契约映射

| 后端事实 | UI 表达 | 允许动作 |
| --- | --- | --- |
| `lifecycle_status=active` | 项目中心正常行 | 移入回收站 |
| `lifecycle_status=recycled` + `recycle_expires_at` | 已回收、倒计时、截止时间 | 恢复项目 |
| `lifecycle_status=purging` | 清理中、已到期、不可恢复 | 无恢复/删除动作 |
| 清理失败且 Worker 等待重试 | 等待后台重试、原因、尝试次数、请求标识 | 无普通员工手动清理动作 |
| `lifecycle_status=purged` | 项目已清理反馈；普通列表不再返回 | 无恢复动作 |

倒计时、恢复资格和清理结果都来自后端生命周期事实；浏览器时间与本地按钮状态不能成为业务权威来源。
