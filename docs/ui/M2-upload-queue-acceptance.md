## 已确认的返工边界

- 上传任务只负责素材上传，不承载术语、中文识别、画面字、前置审改、字幕验收或交付；这些后续流程归任务中心或对应项目工作台。此前三版中的七个流程标签均为错误范围，不作为候选方向。
- 页面只按素材类型、集数和上传状态组织队列；顶部只突出待处理与失败数量。
- 一个任务必须支持一次选择多个素材或素材文件夹，并同时推进多个物理文件；整批总体进度与单素材文字状态/失败恢复并存，不能设计为单一素材上传。

- 行内详情一次只展开一行；默认隐藏相对路径、指纹、会话、分片、完整错误和请求标识。已完成行降低权重并可按完成分组折叠。

## 核心交互

- 批次低频能力不再常驻抢占视线；逐行或选择后的批量能力按状态出现。
- 单文件级：展开详情、暂停/继续、重新选择、重试授权、继续缺失分片、重新上传或读取最新清单；页面按当前状态只突出一个主恢复动作。
- “本机已暂停”与服务端会话状态同时可见，明确暂停不会改变后端状态且会话仍会到期。
- 刷新后先恢复后端清单与分片事实，再要求重新选择原文件；指纹匹配后只续传缺失分片，指纹不符时显示预期/本次选择差异并禁用继续。
- 校验中保持独立状态；进度达到 100% 不提前显示完成。只有服务端返回 `completed` 且完成 Asset 绑定后显示已完成。
- 批次局部失败不遮挡其他文件，失败行常驻并提供原因、稳定错误码、请求标识和唯一恢复动作。

## M2.1 契约映射

- PostgreSQL/后端拥有项目、清单、上传会话、已确认分片、Asset 绑定和项目状态；浏览器只拥有当前文件对象、展示筛选和本机暂停开关。
- 角色标签来自最新已确认清单；队列不得自行补角色或按文件名推断权威绑定。
- 同集 `asr_video` 与 `screen_video` 可共享一个已校验 Asset；公司 SRT、跨集或其他跨类型复用仍禁止。
- 指纹只用于重新选择时防止选错文件，不替代对象大小与校验值的服务端验证。
- `blocked → verifying → uploading → ready → draft` 仅是后端归约优先级，页面不按本地百分比自行计算项目状态。
- 画面字视频明确留空不进入上传队列，也不阻断后端把满足必需角色的项目归约为 `ready`。
