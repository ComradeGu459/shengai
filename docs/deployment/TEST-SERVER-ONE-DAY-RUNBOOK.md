# 测试服务器一日部署与容量演练运行手册

状态：执行中；基础主机、回环 PostgreSQL、37/37 迁移与生产构建已完成，Fastify/两站/压测尚未通过。实时进度、协作角色和用户反馈入口见 [`TEST-SERVER-COLLABORATION.md`](TEST-SERVER-COLLABORATION.md)。
范围：纯净 Debian 12 专用测试服务器、匿名数据、零网络 fake/stub。
硬性禁止：生产主机/数据、真实付费 ASR、COS、Sentry、Secret、供应商网络、购买、提交、推送、发布及自动扩缩容。

## 管理控制台专属边界

部署与容量控制只能通过管理员 `system-frontend` / ControlShell 完成：现有 `/servers`、`/logs`，或后续经 UI 设计批准的管理员测试容量入口。压测起停、故障注入、指标、峰值/长稳状态、报告和停止门均不得出现在员工 `frontend` / AppShell。

员工站在本手册中只作为既有被测服务，验证它与管理员 API、容量事实和控制命令隔离。不得为本次演练增加员工按钮、页面、状态、脚本、文案、测试或浏览器本地控制状态。

## 1. 执行总则

1. 只在规划冻结的主机、DNS/隧道路径、代码快照、匿名夹具和时间窗内执行。任何字段变化都回到“准备核对”。
2. 先部署烟雾与单用户基线，再进行 5→10→25→50→100 的阶梯；每级先预热 3 分钟、稳定观察 10 分钟。任何停止门命中后不升档。
3. 所有写命令使用稳定资源/命令身份和 `Idempotency-Key`。响应未知时只允许同一身份的正式 GET；禁止自动重发 POST、换 ID、扫描列表猜测或制造第二个状态源。
4. 只运行已登记并由后端确认的 Worker。未知 Worker、真实外部适配器、未纳入观察的队列或不具备恢复语义的服务均不启动。
5. 证据只保存聚合指标、时间戳、代码快照、脱敏请求 ID/稳定身份哈希、状态码、错误分类和资源曲线；不保存业务正文、媒体、SRT、对象键、Secret、Cookie/Auth、连接串或供应商载荷。

## 3. 阶段化步骤

### 阶段 0：开通前门禁

**输入**：用户的服务器/SSH/预算授权；规划冻结的目标版本、域名或隧道方案、允许服务、fake/stub 情景和停止门。
**动作**：核对 `TEST-SERVER-PREPARATION-CHECKLIST.md` 全部“部署前验证清单”；记录工作树快照但不清理、覆盖或提交现有脏工作树。
**输出**：已签字的执行清单、资源表、CNY 台账（默认 `¥0`）、回收负责人。
**验证**：目标 IP、数据库、DNS 与任何生产环境无交集。
**停止/回滚**：输入不全、检测到生产地址/凭据或需要购买时，停止并交规划/用户。

### 阶段 1：Debian 12 与网络基线

**输入**：新建测试主机、用户 SSH 公钥、批准的管理源 IP。
**动作**：

- 建立非 root 的部署账户，禁止密码及 root SSH；验证第二把恢复公钥由用户保管。
- 记录 Debian 12、内核、CPU、内存、磁盘、网络规格；安装 Node `24.19.0`、pnpm `11.21.0`、PostgreSQL、Nginx。
- 配置 PostgreSQL 仅本机/私网监听；设置 UFW/安全组仅允许受控 SSH 与 80/443，拒绝 Node/Vite/PG 公网端口。
- 建立应用、数据、日志与临时证据目录，设置权限及日志轮转；不在环境文件写入真实 Secret。

**输出**：脱敏版本和端口核对表。
**验证**：版本精确匹配；外部端口扫描只见批准的端口；从非允许来源不能连接 PostgreSQL；系统磁盘有充足余量。
**回滚**：删除仅本轮创建的系统用户、测试数据库、规则和目录，或销毁明确标识的测试主机。不得删除未核实归属的主机目录。

### 阶段 2：应用构建、数据库与服务注册

**输入**：冻结的代码快照、`pnpm-lock.yaml`、不含值的环境变量模板、匿名 fake/stub 配置。
**动作**：

- 使用 `pnpm install --frozen-lockfile` 安装，运行 `pnpm build`。锁文件不变更时才继续。
- 在专用空测试数据库执行全部迁移；迁移完成、夹具装载前，核对业务行数为零。
- 将员工站和管理站各自构建产物提供给 Nginx；Fastify 仅绑定 loopback。
- 仅为 API 与已登记的、获准的 Worker 建立 systemd 单元。当前可确认脚本见准备清单；缺脚本的 Worker 保持未部署。
- 为 Nginx 写入三个独立 Host；在 admin 没有真实认证时实施 SSH 隧道/IP allowlist + 临时访问门。

**输出**：服务名单、systemd 状态、Nginx 配置语法检查、迁移版本与空库证明。
**验证**：API/Worker 可启动且失败会被 systemd 有界记录；Nginx 不将 work 返回 admin 文件；不存在公开的 `3000/3001/3010/5432`。
**回滚**：停止本轮单元、撤销 Nginx server block、删除仅本轮数据库与构建目录；保留脱敏日志以供诊断。

### 阶段 3：部署烟雾

**输入**：运行中 API、两个静态站、匿名员工/管理员、A/B 项目、零网络 fake/stub。
**动作**：

- 逐一访问 work、admin、api 健康入口；确认 Host、CORS/反代、缓存和错误页各自正确。
- 员工身份不可读取管理员容量 API/页面或控制事实；管理员身份不可借由员工路径获得跨项目事实；A 项目不能读取 B 项目。
- 通过管理员 ControlShell 的既有运行入口观察容量事实；使用已冻结的最小匿名旅程运行一次读取、一次幂等写、一次同身份 GET 恢复和一次 Worker 消费。员工站不承载观察或控制。
- 验证日志/运行记录只有安全投影；检查默认 fake/stub 无外网 DNS/HTTP 出口。

**输出**：烟雾矩阵与脱敏请求计数。
**通过条件**：HTTP 预期状态、零跨站/跨项目泄露、未知响应只产生 GET、Worker/队列可观察。
**停止**：任何权限泄露、跨项目读写、真实网络请求、重复写入或不明费用风险为 P0；立即停止所有服务并冻结证据。

### 阶段 4：单用户基准

**输入**：稳定烟雾环境和一条固定匿名旅程。
**动作**：先预热 3 分钟，再单用户稳定运行 10 分钟。读取路径与有界写路径分别统计；写路径按稳定命令 ID 去重，不能通过提高写次数制造假吞吐。
**输出**：单用户 RPS、p50/p95/p99、错误率、CPU、内存、磁盘 I/O、网络、PG 连接、队列深度、Worker 活跃数和恢复时间基线。
**验证**：所有指标有同一时钟区间与采样间隔；不能采集的指标明确标为 `unknown`，不得填零。
**停止**：单用户已触发容量门时不进入并发测试，交规划定位。

### 阶段 5：阶梯、压力与峰值

每级采用相同的匿名混合比例、预热 3 分钟和稳定采样 10 分钟；通过后才能进入下一档。

| 档位 | 并发 | 时长 | 目的 |
| --- | ---: | ---: | --- |
| S0 | 1 | 10 分钟 | 基线 |
| S1 | 5 | 10 分钟 | 小团队稳定性 |
| S2 | 10 | 10 分钟 | 常规使用 |
| S3 | 25 | 10 分钟 | 首个容量拐点 |
| S4 | 50 | 10 分钟 | 压力档 |
| S5 | 100 | 5–10 分钟 | 短时峰值；只在 S4 通过后执行 |

**动作**：每档记录混合读写比例、请求数、独立身份数、成功/失败分类、队列入/出速率与所有资源指标。压测写入只能落在可回收的匿名库，不以全表清空作为清理方式。
**输出**：每档资源与延迟曲线、饱和拐点、可持续并发建议和峰后队列回落时间。
**回滚**：停止负载发生器 → 等待有界在途任务到终态或进入 unknown/reconciliation → 只 GET 对账 → 停止测试 Worker/API。未知写不得重放。

### 阶段 6：故障注入与恢复

所有故障只对该测试主机、测试数据库和 fake/stub 生效；每次只注入一个变量，另一次运行才组合。

| 故障 | 受控方式 | 必须验证 | 立即停止条件 |
| --- | --- | --- | --- |
| PostgreSQL 短断 | 只短暂停止/隔离测试 PG | API 错误带 requestId；stale 不冒充新事实；恢复后连接池与队列恢复 | 数据损坏、跨项目状态或连接风暴 |
| Worker 退出 | 只停止指定 test systemd Worker | 租约/任务可接管或进终态；无重复付费写 | 第二次副作用或无限重启 |
| 429 | fake/stub 返回固定 429 | 受控退避/明确失败，不重发费用命令 | 自动重复付费 POST |
| 5xx/超时 | fake/stub 固定失败或延迟 | 错误分类、超时、唯一人工恢复路径 | 无界重试或队列持续失控 |
| 响应丢失 | 服务端完成后由 harness 丢弃响应 | 仅 GET 同一身份恢复；命令次数仍为 1 | 客户端二次 POST/新 ID |
| 迟到响应 | fake/stub 延迟旧查询 | 新查询身份不被旧结果覆盖；任务中心一致 | A/B、权限或任务状态被覆盖 |

**输出**：故障起止时间、检测时间、恢复时间、请求/任务身份计数、错误分类、队列峰值与残留数。
**验证**：数据库短断、Worker 重启和响应丢失后，唯一权威状态仍为 PostgreSQL；浏览器、Nginx 和 Worker 不各自保存第二份任务事实。
**回滚**：撤销故障开关、恢复服务、只读对账，确认匿名数据/队列归零后再进入下一项。

### 阶段 7：长稳、导出和回收

**长稳**：在最后一个安全通过档使用 10–25 并发、稳定读写比例持续 1–4 小时。每 5 分钟汇总资源，重点观察内存、PG 连接、队列、Worker 重启、错误率和 p95/p99 是否单向漂移。
**导出**：仅导出聚合 CSV/JSON 或截图：配置版本、档位、时段、指标分位数、错误分类、故障恢复时间、资源峰值、CNY 台账和已知限制。
**回收顺序**：停止负载 → 等待/对账在途任务 → 停止 Worker → 停止 API/Nginx → 导出脱敏证据 → 删除精确命名的匿名测试数据库与夹具 → 撤销隧道、临时 admin 访问门、SSH 临时公钥和 DNS 记录 → 核对监听端口、服务状态、数据库残留和费用为零/已记录。
**完成条件**：回收清单每项都有责任人与验证；未删除的日志只保留脱敏汇总并按留存期自动过期。

## 4. 计划外情形

- 找不到主机指标、数据库连接、队列深度或 Worker 指标：标为观测阻塞，不以 HTTP 成功代替容量结论。
- 负载工具、fake/stub 故障开关或 Worker 启动脚本不存在：停止在部署烟雾前，建立明确缺口包交规划；不临时在服务器手写长期脚本。
- 管理站真实认证尚不存在：不公开 admin；仅使用隧道/allowlist 临时门，且报告中标注该限制。
- 出现任何真实供应商、COS、Sentry、Secret 或费用请求：立即断开外网调用路径，保留脱敏证据并升级为 P0。

## 5. 对规划的交差量包

本手册执行后只交规划，不直接向前端、后端或 UI 派返工：

- 本轮代码/配置快照、服务器脱敏规格、域名或隧道模式、允许服务及 CNY 实际费用。
- 每个并发档的吞吐、p50/p95/p99、错误率、资源峰值、PG 连接、队列/Worker、恢复时间与停止门命中情况。
- 管理控制台独占的容量/停止证据，以及员工站不暴露控制事实的两站隔离、A/B 项目隔离、迟到响应、任务中心一致性、重启恢复和 unknown 只读恢复矩阵结果。
- 已确认瓶颈、可持续并发建议、推荐主机规格、不能作出的结论与未解决依赖。
- 精确回收结果，以及任何未回收资源的名称类别、原因、责任人和到期时间。
