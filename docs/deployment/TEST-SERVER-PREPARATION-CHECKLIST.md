# 测试服务器准备清单

状态：通用准备模板；当前服务器已经进入实际部署，实时事实不要从本模板推断，请统一读取 [`TEST-SERVER-COLLABORATION.md`](TEST-SERVER-COLLABORATION.md)。
适用范围：仅专用隔离测试服务器与匿名测试数据。生产环境、真实付费 ASR、COS、Sentry、Secret、供应商网络、购买、发布和推送均不在本清单授权范围内。

## 管理控制台专属边界

服务器部署状态、容量指标、压测发起/停止、峰值与长稳进度、故障注入、报告和停止控制只属于独立的管理员 `system-frontend` / ControlShell。可复用现有 `/servers`、`/logs`，或等待后续由 UI 设计批准的管理员测试容量入口；不得新增员工容量页面、入口、按钮、状态、脚本、测试文案或第二状态源。

员工 `frontend` / AppShell 仅可作为既有业务界面被动接受匿名访问，以验证它不能读取管理 API、管理运行事实或控制动作。该被测访问不是容量控制能力，也不授权改动员工前端。

## 1. 先决授权与停止条件

开始任何远程动作前，规划对话必须逐项确认：

- 服务器是全新、独占的 Debian 12 测试主机，且不是生产主机、共享数据库或生产公网 IP。
- 用户单独允许本次服务器开通、SSH 登录、软件安装和部署窗口；本文件本身不构成该授权。
- 测试数据仅为手写匿名身份、匿名项目 A/B、固定小型 fake 负载和无业务正文的摘要；不得导入视频、音频、SRT、术语、Cookie、Auth、objectKey、连接串或 Secret。
- 默认使用零网络 fake/stub，外部网络出口在测试进程中保持禁用。真实付费 ASR/COS/Sentry/供应商 API/云资源继续为 **NO-GO**。
- 所有可能发生的费用登记为 CNY。未申请外部资源时，本轮费用上限为 `¥0`。

任一条件无法证明、发现生产地址/凭据、或测试目标不再能与生产隔离时，立即停止，记录脱敏事实并交规划；不得尝试“先跑一次”。

## 3. 网络与访问路径

### 固定拓扑

一台测试主机只使用一个公网 IP；Nginx 依据 Host 分流：

| 入口 | 公开访问 | 上游 | 约束 |
| --- | --- | --- | --- |
| `work.<test-domain>` | 既有员工测试站 | `frontend/dist` 静态文件 | 仅用于既有业务与权限隔离验证；没有容量控制 UI |
| `admin.<test-domain>` | 管理测试站 | `system-frontend/dist` 静态文件 | 容量观测/控制唯一入口；默认不应对互联网开放 |
| `api.<test-domain>` | API | Fastify，仅监听 loopback | 仅 Nginx 反代；不直接暴露 Node 端口 |
| PostgreSQL | 否 | 本机或私网监听 | 不开放 `5432` 公网入站 |

Node/Fastify、Vite 构建产物所需的管理接口和 PostgreSQL 仅监听 `127.0.0.1` 或明确私网地址。公网安全组/UFW 只允许：经批准的 SSH 管理源、`80/tcp` 与 `443/tcp`；拒绝 `3000`、`3001`、`3010`、`5432` 及所有未列端口。

### 域名路径

1. **已具备可用测试域名**：用户将三个测试子域 DNS 指向唯一公网 IP；运维在 DNS 生效后申请测试 TLS 证书，并验证三个 Host 不会串站。
2. **尚无备案/不使用公网域名**：不假定任何地区的备案、合规或可达性结论。默认使用 SSH 隧道加本机 Hosts 映射/本地测试证书访问 `work.test`、`admin.test`、`api.test`；仅经隧道暴露给测试者。该路径不能替代公开互联网、真实 DNS 或公开 TLS 验收。

若需要中国大陆公网可达、公共域名或任何备案相关能力，必须由用户与服务器/域名服务商确认后另行批准；本轮不得通过未备案域名、IP 直连或临时转发规避适用要求。

### SSH 与管理员站临时安全门

- 仅允许非 root 运维账户使用 SSH 密钥登录；禁用密码登录与 root 远程登录，保留第二把用户持有的恢复公钥。
- SSH 源 IP 必须使用用户确认的 allowlist；首次登录前验证主机指纹，结束后撤销临时公钥或规则。
- `admin` 站在尚未具备真实认证/访问代理能力时，必须仅通过 SSH 隧道或明确 IP allowlist 暴露；同时在 Nginx 增加基础访问门并使用独立、短期、用户保管的凭据。该门只是临时测试边界，**不是生产认证**，不能作为公开管理站上线依据。
- 不写入仓库、部署包、shell 历史、测试报告或日志：私钥、基础认证口令、Cookie、Authorization、数据库 URL、证书私钥及任何供应商凭据。

## 4. 主机、服务与数据准备

### 4.1 Debian 12 基线

- 记录镜像标识、内核、CPU 核数、内存、磁盘类型/容量、可用磁盘、网络带宽与区域；报告中仅保留脱敏规格，不保留供应商账号或内部实例 ID。
- 创建受限部署账户、受限日志读取组、应用目录、独立数据目录和独立日志目录；应用目录权限不允许其他系统用户读取环境文件。
- 安装并固定 Node `24.19.0` 与 pnpm `11.21.0`；部署前运行版本检查。不得以系统自带旧 Node 或浮动 `latest` 代替。
- 安装 PostgreSQL、Nginx 与系统安全更新；PostgreSQL 初始化为专用测试集群、专用数据库、最小权限账户，且不含任何生产备份或生产角色。
- 时钟同步、磁盘空间、日志轮转与进程文件描述符上限须在负载前核对；日志以 14 天或更短测试保留策略为准，并只存脱敏字段。

### 4.2 当前仓库可确认的运行方式

本仓库已有 Fastify、员工 `frontend/`、独立 `system-frontend/`、PostgreSQL 迁移与零网络 fake/stub。正式构建由根脚本 `pnpm build` 生成；Fastify 当前可用启动命令为 `pnpm --filter @qimao-terms-cloud/backend run start`。

当前 `backend/package.json` 已登记的后台启动命令只有：

- `start:asr-worker`
- `start:pre-review-worker`
- `start:screen-text-worker`
- `start:strategy-worker`

仓库中虽有其他 Worker entry 文件，但尚未全部拥有对应 `start:*` 脚本。部署时只能为已登记、经后端确认且本轮 fake/stub 场景需要的 Worker 建立 systemd 单元；其余 Worker 不得猜测命令、手写旁路或以守护循环替代。若容量演练需要它们，先由后端任务补齐显式启动/健康/停止契约。

### 4.3 systemd 与 Nginx 资产要求

部署包应在规划派发后生成，至少包括：

- API systemd 单元：明确工作目录、只读环境文件路径、`DATABASE_URL` 引用名、loopback 监听地址、重启限制和健康检查。
- 每个获准 Worker 的独立 systemd 单元：稳定 workerId、单次启动命令、重启策略、日志标签与停止超时；不得共享含业务状态的内存队列。
- Nginx 三个 server block：`work`、`admin`、`api` 的 Host 隔离、静态站点根目录、API 反代、超时/请求体限制、脱敏访问日志与临时 admin 安全门。
- PostgreSQL 配置摘要：仅本机/私网监听、连接上限、应用连接池上限、测试专用备份与恢复演练边界。
- 环境变量清单仅列变量名、用途和来源类别（例如 `fake/stub`）；不包含值、URL、对象键或 Secret。

仓库已提供待审核的 Debian、Nginx、systemd、备份/健康检查和零网络性能 harness 资产，路径为 `deploy/debian/**` 与 `tests/performance/**`。它们只用于静态核查或获得用户授权后的专用测试机，不代表服务器已开通、Nginx/systemd 已安装、监控已接入或负载已执行；Prometheus/Grafana 仍未提供。

## 5. 部署前验证清单

| 检查 | 输入 | 通过证据 | 失败时动作 |
| --- | --- | --- | --- |
| 版本 | Node/pnpm 版本输出 | 精确匹配 `24.19.0`/`11.21.0` | 停止部署 |
