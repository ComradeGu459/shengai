# 审改工作台云端版协作协议（精简）

最后更新：2026-09-01

本协议只定义任务如何派发、交付与停止。项目稳定边界见 [AGENTS](../AGENTS.md)，当前事实见 [CURRENT](status/CURRENT.md)。

## 1. 唯一当前状态

- `docs/status/CURRENT.md` 只记录当前目标、唯一阻塞、下一 Owner、生产基线与最多一项待发布动作。
- `docs/status/ACTIVE_RELEASE.md` 只索引已部署基线和唯一待发布候选，不复制哈希或发布过程。
- 代码、数据库和真实外部状态优先于文档；发现冲突时先停止下一步并修正 CURRENT。
- `docs/logs/`、`docs/status/archive/` 和历史 RESULT 只供审计，不参与调度。

## 2. 轻量任务卡

普通任务卡原则上不超过 8 行，只含：

```text
目标：唯一用户结果
Owner / 范围：角色与精确模块或文件
输入：必须复用的事实、候选或稳定身份
验收：最短可复核证据
停止：越界、冲突、unknown 或需要新权限时的动作
```

普通本地编辑不强制发送 `task_received`、`work_started` 或 `artifact_written`。执行超过 60 秒时，只在出现新信息、里程碑或阻塞时发简短进展；结束时给一次结构化交付。

## 3. 正式 execution lease

正式 lease 只用于会改变外部状态，或可能产生不可幂等、付费、破坏性、不可逆副作用的动作，例如服务器/数据库写入、部署、公开资源、真实 Secret 注入和外部发布。普通本地文档、代码、测试、契约或迁移编辑只使用任务卡中的路径所有权，不登记高风险 lease；发现物理文件重叠时先停止并重新划分 Owner。

lease 只写 Owner、allowed paths、依赖、稳定身份、验收和停止条件；审核或回滚完成后立即清除。同一物理文件同一时刻只有一个可写 Owner。

## 4. 授权边界

- 一次明确授权覆盖同一目标、环境/对象、数据和风险范围内的一个完整切片；低风险本地修正与相称验证不重复确认。
- 只有新增外部写入、破坏性或不可逆动作、购买/付费、真实 Secret/用户数据、公开资源或实质扩大范围时重新询问。
- 外部写入 unknown 时只查询同一稳定身份；未确认结果前禁止重发。
- 平台要求动作任务内确认时，只导航用户一次；不能跨任务代转，也不能用协作消息替代平台确认。

## 5. 角色与上下文换代

- 六个固定角色定义在 `AGENTS.md`；固定的是逻辑职责，不是永久物理任务。
- 只有重大里程碑、上下文被多代废弃方案污染，或完整回读证明物理任务连续空终态时才换代。
- 旧任务只读归档；新任务只继承当前目标、阻塞、关键工具/文件事实、冻结身份和下一步，不复制完整历史。
- 任何中断、归档或换代前，先完整读取目标任务最近回合并核对消息、工具、文件和外部事实；观测为空不能单独证明任务空转。
- 任何时刻只有一个活动规划，不得新旧规划并行派发或建立隐藏代理/worktree。

## 6. 交付与审核

最终交付固定为：

```text
outcome: passed | failed | blocked | rolled_back
files: 实际变更路径；无则写 none
evidence: 本轮最小验证或真实外部事实
external_effects: 外部写入、调用和清理；无则写 none
remaining_gap: 距用户目标仍缺什么
next_owner: 唯一下一责任人
residual: 脏树、临时物或限制
requires_user: false，或唯一所需的新权限/输入
```

规划核对文件、命令和外部事实后，只做四种裁决：完成、同 Owner 定向返工、交下一唯一 Owner、或真实阻塞。代理口述、任务状态或投递成功不能单独证明完成。

## 7. 验证强度

- 小改：复现用例、受影响测试与 `git diff --check`。
- 中型：再加受影响模块 typecheck 与必要 build。
- 共享契约/迁移/高风险数据/发布：增加对应真实门；完整质量门每个里程碑或 release 只跑一次。
- 代码、输入、环境和候选身份未变化时复用已有证据，不为“新鲜”重复数据库测试、全量 `pnpm check`、浏览器矩阵或 Reviewer。
- 新 SDK、Provider、存储或部署方式先查官方文档/官方仓库，再参考一个成熟 GitHub 实现；不并行试多条路线。

## 8. 停止条件

出现任一情况立即停止当前写入并交规划：

- 范围、Owner、数据或权限边界发生实质变化；
- 同一首因第二次仍失败；
- 外部写入结果 unknown、可能重复付费或重复创建；
- 文件所有权冲突、CURRENT 与代码/外部事实冲突；
- 需要第二状态源、长期兼容双轨、现场业务补丁或破坏性清理。

安全回滚后仍需写明目标缺口和下一 Owner；回滚不等于产品完成。
