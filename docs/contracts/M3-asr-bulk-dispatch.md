# M3 S2.1 多剧中文识别、热词证据与费用分层契约

状态：用户于 2026-08-14 确认采用。本文扩展 `M3-asr-batch.md`，不授权真实供应商、密钥、付费、云资源或部署。

## 1. 目标与非目标

员工可以从项目中心一次选择多部已完成素材准备的剧，系统逐项目检查术语版本和 ASR 视频双门禁，明确创建多个项目批次，并在全局中文识别任务视图观察进度。单部剧仍在项目工作台“中文识别”页查看逐集质量、结果和恢复动作。

本切片不是上传任务扩展：上传会话和文件不是批量识别的选择单位；一部剧的 `Project` 才是唯一选择单位。上传完成页只允许把对应项目预选后跳转到批量发起入口，不直接绕过术语与素材双门禁。

本切片不实现真实 ASR、通用 OCR/导出任务中心、字幕正文编辑、播放器、账号、密钥或费用支付。

## 2. 热词必须有三层证据

### 2.1 正确项目绑定

- 批次只能引用属于同一项目的不可变 `TermVersion`；跨项目术语版本稳定拒绝。
- 批次固定 `projectId / termVersionId / manifestId / adapter configDigest / hotwordDigest`，重试继续引用原批次身份；采用新术语版本必须显式创建新批次。
- Worker 执行前从固定术语版本重建热词并核对摘要，不一致时停止执行，不以最新草稿或浏览器副本替代。

### 2.2 实际发送证据

- 增加后端权威热词预览：显示术语版本、实际纳入的中文术语与人名别称、过滤和截断数量、供应商/适配器模式、投影版本及摘要。
- 通用术语候选集不得在进入适配器前用固定的全局 `100 项 / 2000 字` 静默截断。每个适配器按自身能力确定条数、字符、权重和格式，并把实际 payload 摘要与数量写入 Attempt 证据。
- 适配器必须返回热词应用回执：`simulated / submitted / partially_submitted / unsupported / unknown`。`submitted` 只表示请求已携带并被供应商受理，不等于准确率提高；供应商不提供确认时必须显示 `unknown`，不得冒充成功应用。
- 普通运行日志仍只保存摘要、数量、投影版本和请求标识，不复制完整项目术语；员工可在受保护的项目页面查看本项目的权威预览。

### 2.3 真实效果证据

- 真实供应商接入后，用同一获准的 1–3 集样本执行无热词/有热词 A/B 对照。
- 以公司台词和已确认术语版本为标准，至少统计术语应出现次数、正确命中、错误替换、遗漏、跨项目污染、术语召回率和精确率。
- fake/stub 只证明绑定和传递链路，不证明真实音频准确率；没有 A/B 结果时页面只能显示“热词链路已接通，准确率未验证”。

## 3. 多项目批量发起

- 单次选择 `1–20` 个项目；默认入口位于项目中心，上传完成页只负责预选项目并跳转。
- 后端为每个项目计算：项目可编辑、最新已确认术语版本、最新已确认素材清单、ASR 视频覆盖、正在执行批次和可复用结果。
- 确认框必须显示“已选 N 部剧 / 可创建 N 部 / 阻断 N 部 / 总集数 / 预计新任务 / 可复用结果”。
- 局部阻断不得静默跳过。用户可以显式选择“只为可执行项目创建”，返回逐项目结果；阻断项目保持选中并提供返回术语或素材的唯一修复入口。
- 一个幂等的 `ASRDispatchGroup` 保存本次多项目意图、规范化项目集合和每个项目的批次/阻断结果。刷新、未知响应或重复提交不得重复创建项目批次。
- 浏览器在首次提交前只生成一个随机 UUID 作为 `dispatchGroupId`，并把它连同规范化项目集合写入创建请求；该 UUID 只是服务端资源的预分配标识，不是浏览器业务状态。后端必须校验其唯一性、把它纳入幂等请求摘要并以 PostgreSQL 记录为准。
- 创建响应未知时，浏览器已经持有 `dispatchGroupId`，只调用既有详情 GET 重新读取同一 Dispatch；不得扫描列表按项目/时间猜测，也不得自动或以“刷新”名义重发创建 POST。详情暂时 `404` 仍表示创建结果尚未确认，页面保留同一意图和唯一“重新读取”，不据此创建第二个 Dispatch。
- Dispatch 持久化首次创建的服务端 `requestId`，列表和详情刷新后继续返回同一值；后续 GET/取消请求自己的错误请求标识只用于该次错误诊断，不能覆盖创建请求标识。幂等键不得进入普通员工页面、URL或响应体。
- 每个项目批次仍拥有独立状态、取消、失败子集重试和结果历史；批量记录不能覆盖子批次事实。

## 4. 公平并发与扩容

- 当前单 Worker 顺序处理只能称为“多剧排队”，不能称为“多剧同时识别”。
- 员工可同时启动多部剧；剧/项目是发起和进度展示单位，集是后台 API 调用与调度单位。排队中的剧仍是已受理任务，但不得显示成正在识别。
- 开发 fake 的初始安全值为全局 `4` 个逐集任务、每项目 `1` 个；这只是本地模拟默认值，不是正式生产容量承诺。正式 ASR 只走云 API，实际全局、单供应商和单项目在途请求数由系统控制台的生效配置、供应商配额、速率和预算共同决定。
- 调度必须避免最早的大剧长期独占 Worker；在可执行项目之间公平选择，再在项目内按集数升序执行。
- 一个任务失败、阻断或需对账不阻塞其他项目。`reconciliation_required` 永不进入普通自动重试。
- 后续增加 API Worker 进程或服务器时继续依靠 PostgreSQL 租约和 `SKIP LOCKED` 领取，不复制业务状态；增加进程不能绕过系统控制台的全局/供应商在途上限。供应商并发、QPS/RPM、日/月额度、队列上限和预算由系统控制台版本化配置。
- 管理员降低并发只影响尚未领取的集级任务；已被供应商受理的请求继续完成。暂停接收新任务、暂停调度和取消已受理请求是三个不同动作，必须分别显示影响并记录审计。
- 当前员工主站不实现这些管理员控件。Wave B 后端只需把调度器对并发/速率策略的读取收口为稳定内部接口并提供开发默认值；未来管理员网站通过独立管理 API 发布策略版本，员工前端仍只调用项目、Dispatch 和批次业务 API。

## 5. 批次状态对齐

批次正式增加 `cancel_requested` 与 `reconciliation_required`：

- 任一未终结 Job 已持久化取消意图时，批次显示 `cancel_requested`，不能仍显示普通 `running`。
- 没有可用结果且存在需对账 Job 时，批次显示 `reconciliation_required`，不能伪装为普通 `failed`。
- 同时有可用结果和失败、取消或需对账时仍显示 `partial`，详情必须分别给出数量。
- UI、共享 TypeBox、数据库枚举、汇总仓储、筛选排序和测试必须使用同一集合，前端不得自行推导另一套批次状态。

## 6. 员工页与系统控制台费用分层

- 员工项目页主表只显示处理时长、任务数量、质量和“用量已记录/待对账”，不把金额和供应商内部代码作为主要工作信息。
- 独立系统控制台按 Attempt 展示项目、剧集、供应商、模型、供应商请求标识、媒体时长、计费单位/数量、预估金额、最终金额、币种和对账状态。
- 控制台支持按请求、项目、日期、供应商和模型聚合，并区分模拟零费用、预估费用、最终费用和待对账；费用未知不能记为零。
- 员工页和控制台都读取同一 PostgreSQL Usage 事实，不建立第二套费用台账。

## 7. UI 信息架构

1. 项目中心：增加服务端“可识别/缺术语/缺视频/识别中/失败”筛选、逐行选择和选择后批量栏。
2. 批量确认侧栏：逐项目显示术语版本、热词数量、视频覆盖、新任务/复用/阻断和唯一修复入口。
3. 全局任务中心 / 中文识别：只显示跨项目 Dispatch 与项目批次摘要；不上传文件、不编辑字幕正文。
4. 项目工作台 / 中文识别：保留单剧批次和逐集详情，新增本批次热词证据，不承担多项目选择。
5. 系统控制台 / 用量与费用：后续展示每次请求与聚合费用；员工页不复制该管理表格。

## 8. 建议 API 与权威数据

- `GET /api/projects/:projectId/asr/hotwords/preview?termVersionId=...`：权威热词预览、过滤/截断、投影版本和摘要。
- ASR Attempt 读取投影增加热词应用回执和实际 payload 摘要/数量；不返回密钥或对象地址。
- 项目列表增加后端计算的 ASR eligibility 摘要，或提供等价的批量资格查询；浏览器不得根据文案猜门禁。
- `POST /api/asr/dispatch-groups`：请求体携带客户端预生成的 `dispatchGroupId`，幂等创建多项目意图并返回逐项目 accepted/blocked 结果；首次服务端 `requestId` 持久化到 Dispatch。
- `GET /api/asr/dispatch-groups` 与 `GET /api/asr/dispatch-groups/:id`：跨项目任务摘要和恢复。
- 现有项目级批次 API 保持单项目语义，由 Dispatch 服务调用同一领域命令，不复制创建规则。

PostgreSQL 是 Dispatch、批次、热词证据、Attempt、结果和 Usage 的唯一权威来源；浏览器选择、批量栏和筛选只用于交互。

## 9. 分步交付

### Wave A：不阻塞单剧前端

- UI：补热词预览/回执、员工用量简化和新批次状态。
- 后端：补批次状态对齐、热词预览和 Attempt 回执；继续只用 fake/stub。
- 两项通过后立即解锁现有 `FRONT-M3-02B`。

### Wave B：与单剧前端受控并行

- UI：设计项目中心多选、批量确认和全局中文识别任务视图。
- 后端：实现 DispatchGroup、项目资格投影、公平调度和集中并发配置。
- 完成后由前端增加多剧批量入口与跨项目恢复。

S2.1 关闭门：匿名项目能够一次选择至少 3 部剧，其中包含可执行、缺术语和缺视频项目；系统只为用户明确确认的可执行项目各创建唯一批次，默认最多 4 个项目公平推进，刷新后 Dispatch 和子批次一致；热词预览、执行回执、失败重试、取消、需对账和零费用 Usage 均可追溯，完整质量门通过。
