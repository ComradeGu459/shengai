# 本地双应用功能等价迁移矩阵

状态：长期产品验收门禁。本文记录云端是否真正覆盖两个本地应用，不代表所有能力已经实现。

## 1. 权威来源与判定规则

本矩阵的只读权威来源：

- `apps/short-drama-terms-workbench/README.md`
- `apps/short-drama-terms-workbench/compatibility/feature_contracts.json`
- `apps/short-drama-terms-workbench/docs/` 中当前 V3.79–V3.82 交接与热修复说明、对应源码和回归测试
- `apps/short-drama-subtitle-review/README.md`
- `apps/short-drama-subtitle-review/desktop/` 中核心实现、自测与 V3.58/V3.59 更新说明

功能等价不要求照搬桌面布局，但必须同时满足：

1. 同一业务输入能够完成同一或更少步骤的用户目标。
2. 核心输出、证据、人工决定、版本和失败状态没有丢失。
3. 原素材不被覆盖，权威状态可恢复，付费或异步动作不会重复执行。
4. 优化后的行为差异已经写明，并有自动化或真实流程证据。
5. 未实现项保持可见，不得通过删除入口或改名假装已经完成。

状态只使用：`已等价`、`开发中`、`必做未开始`、`用户确认后置`、`用户明确取消`。其中“内部版暂不阻塞”不等于“用户明确取消”。

## 4. 切片立项与关闭门

- 规划在每个后续切片开始前，把相关矩阵行拆到职责矩阵和任务验收，注明本地入口、云端优化方案与非目标。
- UI、后端和前端交付时必须指出覆盖了哪些矩阵行；若发现本地已有能力未被契约表达，按冲突协议暂停并回到规划，不能自行删减。
- 自动化测试证明状态、恢复和数据边界；真实样本验收证明主要操作路径。两者缺一时只能标记“开发中”。
- 最终宣布“云端成品”前，矩阵不得存在 `开发中` 或 `必做未开始`；任何剩余项必须由用户逐项明确选择后置或取消。
