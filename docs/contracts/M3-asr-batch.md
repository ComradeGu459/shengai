# M3 S2 中文 ASR 批次契约

状态：用户已于 2026-08-14 确认推荐方案；本文件是 `UI-M3-02`、`BACK-M3-02A` 和后继 `FRONT-M3-02B` 的产品与数据语义权威来源。

## 1. 用户目标与范围

员工在一部剧的项目工作台“中文识别”模块中，选择整剧、选中集或单集，以已经确认的术语版本约束中文语音识别；可以看到每集排队、运行、成功、警告、失败、取消和需对账状态，并只重试失败集，不重复处理已成功集。

S2 先以零付费、无外部网络副作用的确定性 fake 跑通正式状态、接口和页面。真实中文 ASR API 的供应商选品、密钥、费用与少量样本调用另过授权门；fake 通过不代表真实识别准确率已经验收。

S2 属于项目工作台“中文识别”，不属于全局上传任务。全局任务中心后续只汇总同一批次事实，本切片不另建任务中心。

## 2. 已确认的操作流程

1. 页面读取最新已确认素材清单、已校验 `asr_video` Asset 和不可变 `termVersionId`。
2. 员工选择整剧、若干集或单集；后端把范围规范化为升序、去重的集数集合，并逐集检查双门禁。
3. 页面通过一次服务端准备读取，在提交前逐集展示：集数、来源视频、术语版本、适配器模式、可执行/可复用/阻断事实、预计任务数和已存在可复用结果数；浏览器不得扫描历史批次详情重建复用状态。
4. 员工显式创建批次。相同幂等键和相同规范化请求重放必须返回同一批次；同键异参稳定返回 `409`。
5. Worker 通过数据库租约领取逐集任务。页面显示批次汇总和每集状态；刷新、关闭页面或 Worker 重启不得丢失已提交事实。
6. 成功结果形成不可变 ASR 结果修订；失败、取消或未知结果不得覆盖此前成功结果。
7. 员工可以取消批次。未开始任务终止；已在外部执行的任务进入取消请求或对账状态，不能伪装成已取消。
8. 员工可显式只重试失败集。历史成功集、输出和诊断继续保留；重试创建新尝试，不覆盖旧尝试。

## 3. 双门禁与输入身份

每个逐集任务必须固定以下身份：

- `projectId` 与 `episodeNumber`；
- 最新已确认素材清单版本；
- 已完成服务端校验的 `asr_video assetId` 及内容摘要；
- 不可变且属于同一项目的 `termVersionId`；
- 适配器、模型、语言、配置和热词投影的不可变摘要。

项目不是 `active`、术语版本不存在、集数没有已校验 ASR 视频、素材绑定已变化或同一集存在不确定冲突时，不创建可执行任务；逐集返回明确阻断原因。术语整理仍可与视频上传并行，但识别执行必须同时满足术语和视频双门禁。

同一个物理 MP4 同时承担 `asr_video + screen_video` 时，ASR 只读取既有同一 Asset，不复制上传或创建第二份媒体身份。

## 4. 术语热词投影

- 只从本任务固定的已确认术语版本生成热词，不读取会变化的草稿或浏览器表格。
- 使用八类正式术语的中文术语；人名可以加入已经确认的有效简称/昵称，但过滤“先生、小姐、总、董事长”等普通职位称呼、泛关系称呼、空值、重复项和明显通用词。
- 投影按人名优先、正式类型顺序、字幕首次证据顺序保持确定性。供应商存在长度或条数上限时，由适配器确定性截断。
- 任务必须保存 `hotwordDigest`、纳入的术语/别称数量、过滤数量和截断数量；不在普通日志复制整份敏感术语表。
- 员工必须能在受保护的项目页面查看本批次权威热词预览与投影摘要。批次证据必须按该批次保存的 `termVersionId + provider/adapter/model/language/configDigest + hotwordDigest + capability snapshot` 重建并核对，不能使用读取时的当前默认适配器替换历史事实。
- 批次证据必须分别返回实际纳入项与被省略项；省略项至少包含稳定顺序、原始术语/别称、来源和厂商中立原因码。首期原因码覆盖规则过滤、重复去除、适配器条数上限和适配器字符上限；不得把供应商原始响应或内部对象地址直接暴露给员工页。
- 每次 Attempt 的热词回执除五态外，还要持久化厂商中立事实：实际提交数量、省略数量和可空的稳定原因码。`partially_submitted` 必须可在刷新后恢复已发送/省略数量与原因；`unsupported` 必须明确本次没有应用热词；`unknown` 不得推断为已提交。实际发送回执、供应商限制和多剧发起扩展以 `M3-asr-bulk-dispatch.md` 为准。
- 新术语版本不会静默改写旧结果。旧结果继续显示其实际 `termVersionId` 并标记术语版本已过期；默认只建议重跑受影响集，也允许用户显式整剧重跑。

## 5. 权威数据与状态

PostgreSQL 是批次、逐集任务、尝试、结果、状态、用量和审计的唯一权威来源；消息队列只负责唤醒，浏览器只显示后端投影。

建议最小实体：

- `ASRBatch`：范围、规范化集数、术语版本、适配器配置摘要、幂等命令和汇总状态。
- `ASRJob`：集数、Asset、当前尝试、取消意图、当前可用结果和逐集状态。
- `ASRAttempt`：租约、适配器请求身份、开始/结束时间、错误、用量和诊断摘要。
- `ASRResult`：不可变原始 Cue 集、来源/配置摘要、质量摘要和创建时间。

批次状态只使用：

- `blocked`：一个或多个请求集未满足双门禁，批次未执行；
- `queued`：已持久化，等待 Worker；
- `running`：至少一集正在执行；
- `partial`：已有成功结果且仍有失败、取消或需对账项；
- `completed`：全部请求集已有可用结果或明确复用了完全同源结果；
- `failed`：没有可用结果且任务已确定失败；
- `cancel_requested`：批次取消意图已持久化，仍有逐集任务等待确认终态；
- `reconciliation_required`：没有可用结果且至少一个逐集任务的结果或费用未知；
- `cancelled`：全部未完成项已确认停止，没有外部结果仍未知。

逐集任务状态只使用：

- `queued`、`leased`、`running`、`completed`、`failed`、`cancel_requested`、`cancelled`、`reconciliation_required`。

运行状态和质量状态分开。成功结果另有 `qualityStatus = pass | warning | rejected`；不能用供应商单一置信度直接决定字幕可用性。

## 6. 结果、质量与源文件保护

- 公司 SRT、视频 Asset、ASR 原始结果和后续人工采纳稿必须分开保存；ASR 不覆盖任何原始输入。
- ASR 结果至少保存集数、轴号、开始/结束时间、原始文本和供应商可用时的置信信息。S2 不删除标点、不执行 18/28 字断句、不编辑正文；这些属于 S3 前置审改。
- 质量摘要至少可容纳：音频覆盖、空结果、Cue 数量与公司稿差异、异常长段、时间轴异常、术语命中、低置信片段和已知幻觉信号。fake 只产生确定性匿名质量证据，不冒充真实准确率。
- `qualityStatus = rejected` 的结果保留诊断但不成为当前可用结果；此前更好的成功结果保持可用。
- 完全相同的 Asset、术语版本和配置已有成功结果时，默认复用或跳过；用户显式要求新识别时创建新结果修订，不能覆盖历史。

## 7. 重试、取消与未知结果

- 创建批次、取消和重试命令都必须幂等，同键同参稳定重放，同键异参冲突。
- 只有明确知道供应商未受理或本地执行未产生付费副作用的技术失败，才允许按配置自动有限重试。
- 一旦外部请求可能已经受理但结果未知，任务进入 `reconciliation_required`，不得自动再次付费。未来真实适配器必须先查询供应商请求或由员工显式处理。
- 显式重试默认只包含 `failed` 集；成功、警告和已复用结果不重复。子集重试后，批次历史仍能恢复整剧全部结果，而不是只剩最后一次子集。
- 取消只表达用户意图。已经提交外部供应商且无法撤回的请求仍须保存最终结果/费用事实，不得因页面显示“已取消”而丢失对账。

## 8. fake 适配器与真实供应商授权门

首个适配器固定为 `deterministic_fake`：

- 仅开发和测试环境启用；生产环境默认禁用；
- 不读取真实供应商密钥，不发外部网络请求，不产生费用；
- 通过匿名脚本化输入生成确定 Cue、警告、失败、未知结果、取消和租约恢复场景；
- UI 必须明显显示“模拟识别”，历史记录保存 `provider=fake`，不得冒充真实识别。

S2 同时必须建立可替换的正式适配边界，但不实现任何真实厂商空壳：

- 批次、Job、Attempt、Result、Cue、Usage 和前端人工流程只依赖统一 ASR 领域契约，不依赖某一家厂商 SDK、回调结构或错误码；
- 适配器必须声明稳定的 `provider / adapter / model / language / configDigest` 元数据；共享读取契约允许返回已登记的厂商标识，不把这些字段限定为 fake 字面量；
- Worker 按批次保存的适配器标识从后端登记表解析适配器，默认仍只有 `deterministic_fake`，员工请求不能任意指定未批准厂商；
- 内部执行输入至少能取得不可变 Asset 的 `assetId / objectKey / originalFilename / mediaKind / sizeBytes / checksum`，以及与 `hotwordDigest` 一致的实际热词投影；普通 API 和日志仍只返回热词摘要，不暴露完整术语或对象地址；
- 适配器输出统一映射 Cue、质量、供应商请求标识、可重试/未知结果和标准化用量事实；Usage 持久化不得由仓储写死为 fake，fake 只是返回全零的同构用量；
- 增加第二个仅测试用、零网络的匿名 stub 通过同一注册、执行和持久化路径，证明新增真实厂商不需要修改批次/Job/结果状态机或公开 API 形状；不得因此添加阿里云、腾讯云、火山、讯飞等未授权厂商代码、SDK 或密钥占位。

真实 API 进入前必须另行完成：

1. 基于当前官方文档的中文准确率、热词支持、时间戳、文件上限、异步回调、数据留存和价格选品；
2. 用户明确批准供应商、少量测试范围、预算上限和密钥使用；
3. 密钥只由后端 Worker 从 Secret 引用读取，绝不进入前端、数据库明文、响应、普通日志或截图；
4. 用获准的 1–3 集样本比较术语命中、时间轴、异常长段、费用和失败恢复，再决定主供应商；
5. 真实供应商不满足约束时，可以更换适配器，不改变批次、任务和人工流程的权威语义。

## 9. 用量和成本边界

- fake 用量和费用恒为 0，但仍写入结构相同的用量记录以验证页面和报表。
- 真实适配器必须保存请求音视频时长、供应商计费单位、计费数量、币种、单价版本、预估金额、最终金额和供应商请求标识。
- 服务端配置批次/日/月硬上限和最大并发，普通员工不能在业务页面修改或绕过；超限只阻断新任务，不影响历史读取。
- 真实调用前页面显示可解释的估算；最终以供应商已对账用量为准。费用未知时显示“待对账”，不得显示 0 元。
- 员工页只突出处理用量、质量和待对账；每次请求金额与跨项目聚合进入独立系统控制台，二者读取同一 Usage 事实。
- 当前不购买服务器、不创建云资源、不接真实密钥；供应商价格与服务器方案不写死在本契约，选品时以当日官方资料为准。

## 10. S2 页面边界

正式“中文识别”页至少覆盖：

- 双门禁摘要、当前术语版本与来源视频覆盖；
- 整剧/选中集/单集范围选择和提交前确认；
- 批次列表和每集紧凑状态表；批次编号搜索、行动优先/更新时间排序、分页和总数全部由服务端执行，浏览器不得先取固定上限再做全集搜索或排序；
- 已完成、警告、失败、取消、需对账的中文文字状态和下一动作；
- 批次汇总、真实/模拟标识、用量/费用摘要、请求标识；
- 取消批次、仅重试失败集、查看尝试与质量摘要；
- 加载、空数据、阻断、排队、运行、部分成功、全部成功、失败、取消和需对账状态；
- 1440×900 与 1024×768、侧栏 204/72 两态、键盘和焦点闭环、无页面级横向溢出。

页面不实现字幕正文编辑、公司稿/ASR 对照采纳、视频播放器、OCR、全局任务中心、供应商密钥管理或账号权限。

## 11. 建议 API 语义

- `POST /api/projects/:projectId/asr/batches`：创建整剧/选中集/单集批次，使用 `Idempotency-Key`。
- `GET /api/projects/:projectId/asr/batch-preparation?termVersionId=...`：一次返回当前确认素材清单下的逐集来源视频与可执行/可复用/阻断事实；可选的新识别意图只改变是否复用，不通过扫描历史批次推断。
- `GET /api/projects/:projectId/asr/batches`：服务端分页、状态/批次编号搜索和行动优先/更新时间排序批次；空页仍返回筛选后的真实总数。
- `GET /api/projects/:projectId/asr/batches/:batchId`：批次、逐集任务、尝试、结果与用量投影。
- `GET /api/projects/:projectId/asr/hotwords/preview?termVersionId=...`：只用于创建前预览，返回当前后端路由下的权威热词、数量、过滤/截断和摘要。
- `GET /api/projects/:projectId/asr/batches/:batchId/hotwords`：按批次保存的适配器身份与能力快照返回历史权威纳入/省略证据并核对摘要；不得退化为读取当前默认适配器。
- `POST /api/projects/:projectId/asr/batches/:batchId/cancel`：幂等取消意图。
- `POST /api/projects/:projectId/asr/batches/:batchId/retries`：显式只重试失败/已确认可重试集。
- 后续 S3 只读取不可变 ASR 结果与 Cue，不直接读取 fake/供应商临时响应。

具体字段名由共享 TypeBox 契约实现，但不得改变本文件的状态含义、双门禁、幂等、费用和不可变结果边界。

## 12. 任务拆分与停止条件

- `UI-M3-02`：只设计项目工作台“中文识别”页、状态矩阵和交互证据；不改生产 React。
- `BACK-M3-02A`：实现 PostgreSQL、共享契约、正式 API、数据库租约 Worker、确定性 fake、用量和后端回归；不接真实供应商。
- `FRONT-M3-02B`：等待 UI 与后端分别通过规划审核后，再实现正式 React 页面和真实 fake 链路。
- `BACK-M3-02E`：只补批次绑定的热词纳入/省略证据与 Attempt 回执事实、单剧批次服务端全集查询，以及一次性逐集准备投影；不接真实供应商、网络、密钥、付费或管理员控制面。

S2 关闭标准：匿名数据能够从双门禁创建批次，并由可实际启动、可优雅停止的本地 Worker 执行，经历排队/运行/部分失败/子集重试/取消/租约恢复，最终形成不可变 ASR Cue 和零费用用量事实；刷新后状态一致，成功结果不被失败重试覆盖；第二个零网络测试 stub 证明适配器可替换而不改领域状态机和公开 API 形状；完整质量门通过。真实供应商准确率不属于 fake 切片关闭条件，但进入内部正式试用前必须另过真实 API 授权和样本验收。

多项目批量发起、公平并发、热词发送证据和费用分层属于紧随本切片的 S2.1，权威规则见 `M3-asr-bulk-dispatch.md`；它们不得回塞上传任务或让浏览器维护第二套队列状态。
