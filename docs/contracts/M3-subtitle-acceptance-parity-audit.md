# M3 S5 字幕验收功能完整性审查

状态：规划已裁决，等待 UI Rev 4 与后端编辑闭环验证  
日期：2026-08-15

## 1. 审查原因

用户在方案 A 最终预览中发现没有可明确识别的“新增台词字幕 / 新增画面字”入口。规划因此暂停正式前端，把本地字幕验收应用、S5 产品契约、共享契约与后端、UI Rev 3 原型及前端已写范围逐项对照，避免已有能力只停留在接口或文字说明中。

本审查不改变方案 A 的视觉方向和三栏比例，只修复功能入口、项目接续和历史读写边界。

## 2. 权威结论

1. “字幕”是右栏一级工作页，不是单一轨道。其内部必须继续区分“全部 / 台词 / 画面字”，新增、粘贴和批量操作必须有明确目标轨道。
2. 正式页必须提供可发现的“新增台词”和“新增画面字”。不得用一个会静默默认到台词轨的含糊按钮替代；`Ctrl+N` 在“台词/画面字”筛选下沿用当前轨道，在“全部”筛选下必须先明确选择目标轨道。
3. 删除、多选、复制、剪切、粘贴、撤销和恢复都是 S5 必做能力。高频动作采用紧凑工具栏与快捷键并存，不为每个动作建立大卡片；删除必须说明只删除验收工作副本，不覆盖上游 SRT 或历史版本。
4. 项目中心是云端唯一项目选择器。员工可搜索并打开任意 `active` 云端项目，再进入该项目的“视频字幕验收”；工作台提供“返回项目中心 / 切换项目”入口，但不复制第二套跨项目列表。
5. 进入项目后，页面先读取该项目的验收会话列表：恢复唯一当前可写会话，并允许选择 `released / stale` 历史会话只读查看。刷新保持当前 URL 中的项目与会话，不偷偷切到最新来源。
6. 尚未导入云端的旧本地项目不能被网页直接假装为可读项目。它们必须先经项目创建、素材确认和上传进入云端；旧本地项目数据迁移属于独立后续任务，不塞入 S5 工作台。

## 3. 四层功能矩阵

| 能力 | 本地应用事实 | 契约/后端现状 | UI Rev 3 现状 | 裁决与验收 |
| --- | --- | --- | --- | --- |
| 任意已有项目进入 | “最近任务”可打开保存过的项目；自选导入可建立新项目 | 全局项目列表可搜索并打开 active 项目；S5 会话 API 按 projectId 隔离 | 只显示固定匿名项目，没有切换项目路径 | 项目中心负责选项目；项目上下文提供返回/切换入口，选择任意 active 项目后进入 S5 |
| 当前会话恢复 | 重新打开项目恢复编辑进度 | `GET /projects/:projectId/subtitle-acceptance/sessions` 与按 ID 详情已存在 | 未展示会话选择和历史边界 | 优先恢复唯一可写会话；无可写会话时显示新建；历史会话只读可选 |
| 来源版本选择 | 自动联动与自选导入互不偷换 | 创建会话可固定明确的台词 Release 和可选画面字 Release | 只有“会话草稿”摘要，无来源选择入口 | 新建会话面板显示默认最新来源，并允许明确选择已有版本；刷新不改已冻结来源 |
| 台词/画面字筛选 | 右栏有“全部 / 台词 / 画面字” | Cue 有 `dialogue / screen_text` 轨道 | 右栏只有混合“字幕 / 问题” | 保留“字幕 / 问题”一级页签，在字幕页内恢复三种轨道筛选 |
| 新增台词 | 当前筛选为全部或台词时在播放头新增台词，默认 2 秒 | `add` 接受 `track=dialogue` | 只有含糊的“播放头新增”且演示默认单一字幕 | 明确“新增台词”；从播放头起 2 秒并受视频结尾约束，创建后定位到新 Cue |
| 新增画面字 | 当前筛选为画面字时在播放头新增画面字 | `add` 接受 `track=screen_text` | 没有明确入口 | 明确“新增画面字”，与台词共用安全时间规则，不依赖必须先有 OCR 候选 |
| 删除 | 可删除选中台词或画面字，二次确认且不改源文件 | `delete` 支持 1–100 个 Cue | 无可发现删除入口 | 字幕工具栏提供“删除选中”；确认中列出轨道、数量和只改工作副本说明 |
| 多选/复制/剪切/粘贴 | Ctrl/Shift 多选；复制、剪切、粘贴保留相对时间和轨道 | `cut/paste` 与多操作命令已存在 | 无可发现工具栏或选择摘要 | 提供紧凑工具栏、选择数量和快捷键提示；跨轨粘贴必须明确目标轨道 |
| 文字与时间修改 | 文字、入点、出点、移动、I/O 和时间轴拖动 | `update/move` 已存在 | 文字与时间输入存在，时间轴拖动未在原型证实 | 正式 React 必须覆盖表单和时间轴两种入口，统一写同一条件命令 |
| 撤销/恢复 | 本集编辑快照可撤销/恢复 | 不可变编辑事件与 undo/redo API 已存在 | 仅有按钮外观 | 后端专项验证新增/删除/剪贴后可撤销恢复；前端验证真实状态和焦点 |
| 人工问题 | 当前时间、轨道、备注可新增并处理 | create/resolve/waive API 已存在 | 只展示静态问题和处理理由，缺少“新增问题” | 问题页提供紧凑“记录问题”，可绑定当前时间/轨道/Cue；解决或豁免需真实理由 |
| 逐集/整剧通过 | 通过并下一集、整剧预检与批量通过 | 后端已完成同步预检、逐集/子集通过和发布门禁 | 已有主要交互 | 保持 Rev 3 通过项，不因本轮重做 |
| 局部返工 | 受影响集/轨道单独返工 | 返工 API 与历史链路已存在 | 原型未提供明显入口 | 放在问题/更多操作，不占用唯一主操作；明确集、轨道、原因 |
| 历史发布 | 冻结版本可重新打开查看 | Release 列表与 stale/released 只读播放已存在 | 未展示历史版本选择 | 会话/版本选择器显示状态、来源版本、时间和只读原因；历史不得出现写动作 |
| 清空当前任务 | 只解除当前任务，不删项目/源文件/导出 | 云端项目和会话由 PostgreSQL 持有 | 无对应动作 | 云端等价行为是离开工作台/返回项目中心；不得新增会删除项目的“清空”按钮 |

## 4. 集中修正范围

### UI-M3-05 Rev 4

- 保留方案 A、颜色、三栏几何和预检交互不变。
- 只补项目上下文/会话选择、字幕轨道筛选、明确双新增、删除/多选剪贴板工具栏、人工问题入口和历史只读投影。
- 交互不得堆成配置墙：右栏仍只有“字幕 / 问题”一级页签，字幕页内使用一行筛选和一行紧凑工具栏。
- 用同一原型证明“选择已有项目 → 恢复可写会话”“选择历史会话 → 全写锁”“新增台词”“新增画面字”“删除/剪贴板”“记录问题”六条路径。

### BACK-M3-05C

- 不新增迁移或接口；只对现有 `add/delete/cut/paste/undo/redo` 做高价值回归。
- 必须分别证明台词和画面字新增、播放头安全时间、批量删除、跨轨明确粘贴、幂等重放/冲突、撤销恢复和计数/问题/发布门禁同步。
- 若真实测试发现现有实现缺陷，只修同一状态机根因；不得扩大到 UI、媒体代理、真实服务或数据迁移。

### FRONT-M3-05B

- UI Rev 4 和 BACK-M3-05C 经规划通过前继续暂停。
- 恢复后仍沿用 Rev 1，不重写已完成的 `api.ts/model.ts` 安全雏形；按最终矩阵一次实现并提供与 UI 同状态同视口证据。

## 5. 非目标

- 不把本地磁盘项目选择器复制到网页；浏览器不能绕过上传直接读取其他员工电脑的本地历史。
- 不在 S5 重跑 ASR/OCR、导入素材、迁移旧本地数据库、删除项目或管理云资源。
- 不改变用户已选择的方案 A，也不重新开放 B/C、主题定制或栏宽设置。
