# M3 S4 画面字 OCR 工作台契约

状态：用户已确认的产品与数据边界。UI、后端和前端必须共同遵守；聊天记忆、旧桌面布局或单一供应商能力不能覆盖本文。

## 1. 目标与位置

画面字模块把一部剧中需要翻译或交付的非台词画面文字转成可审核、可恢复、可追溯的画面字字幕轨，并发布不可变的画面字 SRT。完整主线调整为：

`上传 → 术语确认 → ASR 与画面字 OCR 可并行 → 前置审改台词 → 视频字幕验收（台词轨 + 画面字轨）→ 交付`

本模块归属“项目工作台 / 画面字”。员工在项目内发起和审核；跨项目运行记录后续进入任务中心；引擎、密钥、并发、费用、抽帧参数和策略版本以后只由独立系统控制台管理。

## 2. 本地能力继承与云端优化

必须保留两个本地应用中已经可验证的结果和保护规则：

- 每个候选关联集数、视频时间、代表截图、OCR 原文、置信度、位置、分类和来源。
- 支持待确认、保留、忽略、人工修改、恢复和批量裁决；人工决定不能被重跑覆盖。
- 支持人工修改文字、入场和出场时间；时间必须合法且不超过权威视频时长。
- 同时出现的左、右独立画面字必须能拆成两个字幕轴；不能把“（左）/（右）”两段合并成一条交付轴。
- 人名条可依据已确认术语把姓名与核心身份整理为两行，但没有证据时不得臆造身份。
- 失败或空结果只重试对应集；已经成功并经人工确认的结果不被批量重跑清空。
- 最终按集形成画面字 SRT；源视频、原始 OCR 结果和历史发布版本不可被覆盖。

云端不照搬本地 Python 路径、引擎设置窗口、输出文件夹选择或桌面补丁结构。刷新恢复、并发控制、错误状态、审计事件和不可变版本统一由 PostgreSQL 持有；对象存储只保存视频和派生截图等字节对象。

## 3. 启动门禁与固定身份

创建 OCR 批次前必须同时满足：

1. 项目为 `active`。
2. 存在最新已确认的素材清单。
3. 目标集存在已完成的 `screen_video` Asset；同一物理 MP4 可同时绑定 `asr_video` 与 `screen_video`，但只能上传一次。
4. 项目存在已确认的不可变 `TermVersion`。
5. 没有与同一项目、同一素材清单和同一范围冲突的活动 OCR 批次。

每个批次必须固定项目、素材清单版本、目标集集合、每集视频 Asset、术语版本、OCR Adapter/模型/语言、能力快照、抽帧与去重策略版本、配置摘要和首次服务端请求标识。后续配置或术语变化不能改写历史批次；素材来源变化使旧工作区进入只读 `stale`，不得冒充仍可发布。

员工可以选择整剧、选中集或单集，但不能选择供应商、模型、密钥、并发或费用档位。

## 4. 识别范围与确定性初筛

默认保留候选范围包括：

- 人名条及人物身份说明；
- 地点、时间、章节、标题和场景提示；
- 手机聊天、通知、信件、屏幕界面和关键剧情文字；
- 其他需要翻译、统一术语或进入正式画面字轨的文字。

确定性规则可以把下列内容标记为“建议忽略”：与同集同期台词高度重复、纯数字噪声、明显无交付意义的水印或固定模板、已确认的无关提示。规则只能生成可解释建议，不能删除候选或覆盖人工决定；员工可以恢复。

本地规则优先。未来 AI 复核只处理歧义、低置信或抽样候选，停用、失败或超预算不能阻断人工流程。首个实现只使用零网络、零费用的确定性 Adapter 固定业务契约；真实 OCR API、真实密钥、付费和云资源另过授权门。

## 5. 抽帧、去重与证据

OCR Worker 的标准流水线为：

`读取视频元数据 → 自适应抽帧 → 画面变化筛选 → 相似帧去重 → OCR → 空间分组 → 连续帧合并 → 术语提示 → 生成候选和代表截图`

必须保存原始探测帧数、实际 OCR 帧数、去重数量、候选数量、失败集、处理时长和同构 Usage。代表截图作为派生证据保存，数据库只保存 Asset/对象引用、摘要和元数据，不保存大体积 base64。

底部台词区域可以只从“变化判断”中排除以减少重复探测，但不能因此裁掉送入 OCR 的完整画面，避免遗漏低位提示或手机消息。具体区域、采样上限和阈值属于管理员策略，不出现在员工页面。

## 6. 术语约束与可验证回执

Worker 必须从批次固定的 `TermVersion` 生成引擎中立的术语提示投影，并保存：

- 实际纳入、规范化、去重和省略的条目数量；
- 稳定摘要及省略原因；
- 候选命中的人名、别名、地名或其他专名证据；
- Adapter 实际收到的投影版本和配置摘要。

员工页面显示“使用术语 Vn、已发送 N 条、命中 N 个候选”等业务证据，不显示热词正文全集、供应商密钥或管理员配置。不能只显示“已对接术语”而没有后端可恢复事实。

## 7. 状态与数据所有权

PostgreSQL 是以下事实的唯一权威来源：

- `ScreenTextBatch`：批次、范围、固定配置、汇总状态和 Usage；
- `ScreenTextEpisodeJob`：逐集租约、进度、失败、取消和重试关系；
- `ScreenTextAttempt`：每次实际调用的配置、输入摘要、回执和对账状态；
- `ScreenTextCandidate`：不可变 OCR 原始事实、代表截图和空间/时间证据；
- `ScreenTextDecisionEvent`：保留、忽略、恢复、修改、拆分和人工新增事件；
- `ScreenTextDraft`：当前可编辑投影及修订号；
- `ScreenTextRelease`：不可变画面字版本、逐集 Cue 和确定性 SRT。

逐集状态至少包括：`not_started`、`queued`、`running`、`review_pending`、`completed`、`confirmed_empty`、`failed`、`cancel_requested`、`cancelled`、`reconciliation_required`、`stale`。

候选人工状态至少包括：`pending`、`approved`、`edited`、`rejected`。系统建议是独立字段，不得伪装成人工状态。

## 8. 人工工作台与操作规则

正式桌面页面保持一个项目上下文，采用三栏结构：

- 左侧：集列表、逐集状态、待确认/保留/忽略/失败数量和范围筛选；
- 中间：紧凑候选表格，支持服务端搜索、状态/分类筛选、排序、当前页选择和显式跨页全选；
- 右侧：代表截图与同源视频定位、OCR 原文、术语命中、分类、位置、文字和起止时间编辑。

页面顶部只有一个主要识别入口，选择整剧、选中集或单集后发起。任务状态可在本页看到，但供应商、模型、密钥、并发、金额和策略墙不进入员工页面。

允许的人工动作：保留、忽略、恢复、编辑文字、编辑时间、修改分类/位置、拆分左/右双轴、人工新增。所有写入使用项目、草稿修订和幂等键；网络未知只恢复同一意图，确定性冲突刷新权威事实后由用户重新提交。

“选择全部待确认候选 → 全部采用”是显式动作。普通当前页选择不能偷偷跨页；筛选条件改变候选成员集合时必须清除跨页全选。批量局部失败逐项回显，不能用一个总成功覆盖失败项。

## 9. 空结果、失败、取消与重试

- OCR 返回零候选不等于本集已经完成；员工必须明确确认“本集无画面字”，形成 `confirmed_empty` 事件。
- 失败或空结果可以只重试对应集，并允许 Adapter 按管理员路由切换备用实现；员工只看到“重新识别失败集”。
- 取消只作用于未终结 Job，已经形成的不可变成功结果、人工决定和 Usage 不被删除。
- Worker 使用数据库租约，可停止、可接管；一次租约只处理有界任务。
- 付费或结果未知时进入 `reconciliation_required`，不能无限自动重试或重复计费。
- 重跑产生新批次或新 Attempt；原 OCR 事实、人工事件和历史发布版本保留。

## 10. 完成门禁与发布

创建不可变 `ScreenTextRelease` 前必须满足：

1. 所有目标集处于 `completed` 或 `confirmed_empty`；
2. 没有 `pending` 候选、未处理失败或需对账任务；
3. 每个保留项文字非空，起止时间合法且不超过视频时长；
4. 同一画面左右独立文字已经拆成独立 Cue；
5. 人名条整理只使用术语或画面证据，不含臆造身份；
6. 项目、素材清单、术语版本和草稿修订仍与发布请求一致。

发布必须以一个幂等事务固定 `ScreenTextRelease + Cue + Export` 身份；刷新后可读取同一版本和下载原文件。输出使用 UTF-8 BOM、按集自然排序的画面字 SRT。位置、截图、置信度和审核事件保存在系统内，不增加正式交付文件；同时出现的左右独立文字只在确有成对证据时追加“（左）/（右）”。

画面字 SRT 是后续字幕验收的只读输入，不直接成为最终交付。字幕验收冻结后，交付产品库才组合台词 SRT、画面字 SRT 和术语 XLSX。

## 11. API、密钥与管理员后台边界

浏览器只调用本系统后端，永远不能获得 OCR/AI 密钥。后端 Adapter Registry 必须显式区分 `cloud_api`、`self_hosted_worker` 和 `deterministic_fake` 三类执行方式，并统一描述稳定 adapter ID、provider、model、language、deployment、能力上限、输入/输出版本和配置摘要。项目、批次、候选、人工裁决和发布契约不得因引擎类型改变。

本轮不调用真实网络，但必须至少用 deterministic fake 加两个零网络测试 stub（模拟云 API、模拟本地 Worker）通过同一“正式 API 创建 → Registry 解析 → Worker 执行 → PostgreSQL 落账 → API 读取”链路，证明以后接入厂商或自建引擎不需要重写员工页面和业务状态。批次必须保存实际使用的 adapter 类型、deployment 和能力快照；员工响应只返回业务所需的中立描述，不暴露内网地址、对象键、密钥引用或供应商私有参数。

首个 S4 切片只实现通用 Registry、零网络确定性 Adapter 和完整业务闭环。以下事项后置为独立授权任务：

- 真实 OCR 供应商选品、SDK/HTTP 接入和凭据；
- 真实费用、预算、限流和管理员调度页面；
- 自建 GPU/CPU OCR 服务与容量演练；
- 跨项目学习智能体、提示词/风险词自动优化发布；
- 通用任务中心、画面风险、人脸风险和最终字幕验收。

## 12. 任务拆分与关闭门

- `PLAN-M3-04`：本文、里程碑、职责矩阵和等价矩阵；用户确认后关闭。
- `UI-M3-04`：只设计项目内画面字工作台、状态矩阵、截图/视频证据、批量裁决、时间编辑和发布门禁；不改生产 React。本次用户已明确把 UI 方向验收一次性委托给规划，规划使用现有设计系统、成熟生产工具参考和 Impeccable 有界审查直接裁决，不再等待用户逐张确认。
- `BACK-M3-04A`：共享契约、增量迁移、批次/Job/Attempt/Candidate/事件/Release、租约 Worker、术语投影和确定性 Adapter；不接真实网络或付费。
- `FRONT-M3-04B`：等待 UI 规划代理验收与后端规划验收后，实现正式 React 并通过同状态高保真验收。

S4 关闭至少证明：匿名三集包含正常候选、左右双轴、人名条、同期台词重复建议忽略、人工编辑时间、明确空集和失败集重试；刷新不丢状态，重跑不覆盖人工决定，发布形成不可变画面字 SRT；正式浏览器覆盖 1440×900、1024×768 侧栏两态、加载/空/失败/再次失败/恢复成功/提交中与键盘焦点；最终完整 `pnpm check` 通过。
