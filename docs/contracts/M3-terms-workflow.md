# M3 术语提取、人工确认与版本契约

状态：`PLAN-M3-01` 已获用户确认，作为 M3 S1 产品与数据权威基线。实现任务仍须遵守 `CURRENT.md` 的独立范围和规划总线路由。

本契约融合用户最新术语提示词与原本地工作台已经验证的高召回、证据、人工裁决和版本机制。用户最新业务定义优先；旧应用只作为工程行为参考，不复制旧数据库、缓存、凭据或代码。

## 1. 本切片目标与边界

一部剧的最新已确认公司 SRT 上传并校验后，员工可以：

`提取全剧术语候选 → 查看真实字幕证据 → 逐项确认/修改/驳回或人工补充 → 显式确认不可变术语版本 → 下载正式 XLSX`

术语属于“项目工作台 / 术语”，不属于全局上传任务。S1 不运行 ASR/OCR，不播放或编辑视频，不建设任务中心、跨项目学习库、账号权限或正式交付产品库。

## 2. 正式术语类型

正式版本只允许以下八类，按下表顺序分组；同类内部按首次字幕证据的集数、轴号排序。人名组始终排在最前。

| 顺序 | 正式类型 | 口径 |
| --- | --- | --- |
| 1 | 人名 | 所有具有固定指代的角色名；全名进入“中文术语”，简称、昵称、固定职位/场景称呼进入“别称” |
| 2 | 地名 | 国家、城市、院校、宫殿、住宅、地点等；同时具有地点和机构属性时，地点属性成立则优先归地名 |
| 3 | 特定物品 | 有专名或强标识、推动剧情且具有特殊意义的信物、关键道具；专属交通工具也并入本类 |
| 4 | 朝代 | 古装、穿越等题材中的真实或虚构朝代、时代 |
| 5 | 组织名 | 公司、门派、机构、平台等；家庭与公司是不同实体，不因简称相近而自动合并 |
| 6 | 等级 | 官阶、修炼、门派等体系化阶级；不包含某个人的职位称呼，也不收普通职场职级链 |
| 7 | 物种/种族名 | 虚构物种、族群、特殊群体；有专名并参与核心剧情的非人个体也归入本类 |
| 8 | 特殊概念/事件 | 科技、魔法、功法、特殊体质/能量、关键案件和专名事件等直接推动剧情的设定 |

旧工作台中的“角色称谓/称号”并入对应人名的别称；“特定交通工具”并入特定物品；“特定生物”并入物种/种族名；“功法、特殊体质、特殊能量、事件”并入特殊概念/事件。“病症”和“其他”不作为正式类型：普通疾病直接排除，只有具有专名或虚构设定且直接推动核心剧情的病症才可归入特殊概念/事件；“其他”候选必须人工改成八类之一或驳回后才能确认版本。

## 3. 纳入、别称、备注与去重规则

### 3.1 纳入优先级

1. 类型专用规则优先于通用频次规则。具有固定指代的人名即使只出现一次也应成为候选，避免遗漏一次性具名角色。
2. 物品、概念、事件、等级等非人名术语必须满足“固定指代、翻译需统一、非通用或具有特殊剧情意义”。频繁出现只是证据之一，不替代剧情作用判断。
3. 每个候选至少有一条可回到真实 SRT 的证据；模型无法对应到真实字幕轴的臆造项不得进入人工队列。
4. 普通生活物品、泛称亲属/职位、通用事件、常见疾病和没有固定指代的描述不纳入。

### 3.2 人名与别称

- “中文术语”只写可确认的全名；模型只发现简称时保留为低置信候选，等待人工补全全名，不把简称伪装成全名。
- 简称、昵称、姓氏加职位、固定称号和场景称呼可进入别称，但必须有证据证明指向同一人物。例如“张总裁、张董、叶将军”可保留；裸词“总裁、董事长、爸爸、妈妈、老公、老婆”等没有稳定唯一指代时排除。
- 错别字、同音误写不作为别称；确认正确写法后只保存规范名称，并把错误形式留在内部证据/审计中供后续纠错。
- 同一个名称只能进入一个正式类型；全名优先于局部名字，局部名字可并为别称。不同人物、不同家族和不同公司不得仅凭近似文本自动合并。

### 3.3 备注

- 人名：只写与男女主的直接关系或核心身份，不堆叠无关人物关系。
- 地名、组织名：明确与男女主或核心人物的具体关联，不写“剧中相关地点/机构”等空话。
- 特定物品：说明出现背景、特殊意义和推动的核心情节。
- 物种/种族名：说明与核心人物的关系或对剧情的影响。
- 特殊概念/事件：说明它在剧情中的直接作用。
- 无法由字幕可靠判断的性别或备注不得由模型编造；候选保留“待人工补充”提示，正式确认前由员工补全或确认留空。

## 4. 候选生成流水线

1. **锁定来源**：读取最新已确认素材清单中全部 `company_srt` 绑定，且对应 Asset 必须已校验。术语来源身份使用按集数、Asset ID 和内容校验值生成的 `sourceSrtSetDigest`；只更换视频不会让术语过期。
2. **解析全剧**：按集数和 SRT 轴号生成稳定 Cue，保留源文件、集数、轴号、开始/结束时间和原文。解析失败必须定位到具体文件/轴，不得跳过后伪装完整。
3. **本地高召回索引**：零付费扫描全剧，建立可能的人名、组织、地点、专名短语及全部命中证据，作为 AI 漏项保护和证据重建依据。
4. **AI 分类整理**：使用本契约对应的版本化提示词，对全剧或有重叠的分块文本进行归类、合并别称和生成精准备注。模型输出只产生候选，不能形成正式版本。
5. **确定性校验**：服务端验证类型、真实证据、全名/别称关系、重复项和排除规则；无真实证据的项丢弃并记录诊断。AI 漏掉但本地索引命中的可疑专名进入低置信待复核，不能静默消失。
6. **人工裁决**：员工处理全部候选并可人工新增遗漏术语。刷新后继续读取后端草稿，不依赖浏览器内存。

长度在模型单次可靠上下文内时优先整剧处理；超过上限时自动分块、保留重叠并在服务端合并。员工不需要理解 Pro/Flash、Token 或分块参数。默认以一次主提取加确定性复核控制成本；只有超长剧、格式异常或高召回索引存在未解释缺口时，才触发第二次 AI 复核。真实模型、费用、密钥和调用上限另过授权门。

## 5. 人工裁决与页面结构

候选状态沿用旧工作台已经验证的四态，但页面使用中文：

| 内部状态 | 页面文案 | 含义 |
| --- | --- | --- |
| `pending` | 待确认 | 尚未作出人工决定 |
| `approved` | 已确认 | 原候选内容不变并通过 |
| `edited` | 已修改 | 人工修改后通过；人工新增也记为本状态 |
| `rejected` | 已驳回 | 不进入正式版本，但保留审计记录并可恢复为待确认 |

正式状态转换固定为：`pending` 才能确认或驳回，`rejected` 才能恢复为 `pending`；编辑会形成 `edited`，但只能发生在仍然有效的活动草稿中。前端不得把已确认、已修改或已驳回项送入普通批量确认/驳回，后端也必须拒绝绕过页面发起的非法状态转换。

候选写入、批量裁决、人工新增和版本发布都必须同时满足：项目生命周期为 `active`、草稿来源摘要仍等于最新已确认公司 SRT、当前没有会让该草稿失效的提取运行。任一条件不满足时，页面保留证据、草稿和历史版本只读，后端返回稳定冲突而不是继续写入；不能只依赖按钮禁用保护数据。

正式术语页复用全站外壳，不另造独立视觉体系：

- 页首只显示来源覆盖、提取状态、待确认数、当前导出模板和唯一主操作；不同时堆叠多个同级主按钮。
- 工具栏提供搜索、状态筛选、类型筛选和排序；不把八种类型全部做成拥挤的一级标签。
- 紧凑表格列为：勾选、中文术语、类型、别称、首次出现、证据数、状态、主操作、三点菜单。
- 点击行或证据数打开同页侧栏，显示备注、性别、全部证据及“第几集/第几轴/时间/字幕原文”；S1 不在此嵌入视频播放器。
- 人工新增的真实 Cue 选择必须消费服务端分页，能够到达当前来源的任意 Cue；搜索、集数筛选或翻页时保留已经勾选的证据，并清楚显示已选数量，不能把固定前 30 条当作全部来源。
- 行内主操作只保留“确认”；编辑、驳回、恢复和查看审计等低频动作进入编辑侧栏或三点菜单。
- 表头勾选只选择当前页；随后必须出现明确的跨页入口“选择本草稿全部 N 项待确认候选”，不能让员工误以为当前页等于全部结果。搜索或筛选存在时，跨页入口仍须明确作用于整个草稿的全部 `pending`，并提示不会纳入已驳回项。
- 部分选择时，批量栏允许“批量确认”和“批量驳回”；覆盖本草稿全部 `pending` 时，主动作切换为“全部采用并导出 XLSX”。该快捷路径按“分批确认全部待确认项 → 确认不可变术语版本 → 按当前模板版本下载”顺序执行。
- 批量操作逐项落账并回显局部结果；任何一项失败时保留已成功结果，停止创建版本和导出，列出失败项及下一动作。不得静默采用 `rejected`，也不得把筛选隐藏项误算为已经人工检查。
- 当没有待确认项时，主操作为“确认并导出 XLSX”；来源已变化、提取失败或 SRT 未全部就绪时，上述两种确认/导出动作均禁用并显示唯一可执行下一步。

## 6. 权威数据与不可变版本

PostgreSQL 是唯一权威来源，最小实体职责为：

- `TermExtractionRun`：来源摘要、提示词版本、模型/参数摘要、状态、用量、错误和显式重试。
- `TermCandidate`：当前草稿中的类型、规范名称、别称、性别、备注、来源、置信度和四态。
- `TermEvidence`：候选关联的 SRT Asset、集数、轴号、时间和原文。
- `TermDecisionEvent`：不可变人工确认、修改、驳回、恢复和新增记录；无账号阶段预留操作者字段但不伪造身份。
- `TermVersion` / `TermVersionItem`：员工显式确认后生成的不可变快照，固定 `sourceSrtSetDigest`、提示词版本和正式条目。

只有全部候选离开 `pending` 且来源摘要仍匹配时才能确认版本。确认后再次编辑不会覆盖原版本，而是从最新版建立新草稿；再次显式确认生成 V2、V3。ASR/OCR 后续任务必须引用具体 `termVersionId`，不能读取会变化的“当前表格”。

公司 SRT 发生内容变化时，旧版本和旧识别结果继续保留审计事实，但项目显示“术语来源已更新”；新启动的正式识别必须先形成匹配新 `sourceSrtSetDigest` 的术语版本。系统不得自动重跑付费识别或覆盖人工结果。

## 7. 正式 XLSX 输出

正式下载的数据语义固定为五个标准字段，且只导出 `approved + edited`：

`类型 | 中文内容 | 别称 | 性别 | 备注`

- `别称` 使用 ` / ` 分隔；没有内容时写空单元格，页面可显示“—”。
- 非人名的性别写空；未知且未确认的性别不得猜测。
- Sheet1 按“八类正式顺序 → 同类首次证据顺序”输出。
- 证据、置信度、审核状态和模型信息留在后端审计，不塞进正式五列表。首期不要求额外可见审查工作表。
- 导出从已确认不可变版本生成，不从浏览器表格或临时候选直接拼装。
- “确认并导出”与“全部采用并导出”的最后发布阶段必须使用一个后端幂等命令，在同一事务中创建/重放 `TermVersion + TemplateVersion + TermExport` 绑定；浏览器不得先确认版本、再以第二个独立请求碰运气创建文件。网络未知结果或刷新后重试必须恢复同一版本和同一导出绑定，不得留下“版本已确认但没有本次 XLSX”的半完成状态，也不得因重试重复生成版本或导出。

现有模板已核对为 `类型、中文内容、别称、性别、备注` 五列，示例数据只用于模板说明，正式导出必须移除示例行。

### 7.1 公司级导出模板

- S1 增加公司级导出模板管理，由后端保存并作为唯一权威；首个默认模板等同于现有五列表头和顺序。
- 首版只允许编辑模板名称、五个标准字段的显示表头和列顺序。五个字段都必须且只能出现一次，不允许删除标准字段、增加任意业务字段、改变字段数据类型或借模板修改术语内容。
- 每次保存创建新的不可变模板版本并可设为当前启用版本；旧模板版本保留，不能原地覆盖。模板变化只影响后续导出的表头与列顺序，不改变候选、术语版本或历史文件。
- 确认/一键采用时必须在确认框中显示将使用的模板名称与版本，并把该模板版本绑定到导出请求。重新下载同一导出时继续使用原模板版本，避免后来改模板导致历史结果漂移。
- 术语页提供“模板管理”入口和编辑窗口；当前没有账号权限系统，首期作为受整站访问保护的内部管理能力，未来再限制为管理员，不在本切片实现审批或多租户。

## 8. API 密钥、内部入口与控制台

任何 AI/ASR/OCR 供应商密钥都不得进入前端源码、构建产物、浏览器存储、网络响应、错误详情或普通业务日志。员工浏览器只调用本系统后端；后端 Worker 在服务端读取密钥并调用供应商。

### 8.1 两个控制台必须分开

1. **云平台密钥控制台**：只由部署所有者使用，用于首次写入、替换、撤销原始密钥。密钥存入部署平台 Secret/Key Vault/Secrets Manager 一类专用设施；保存后不提供明文回显。首版不让本网站持有“修改密钥库”的高权限凭据。
2. **网站业务控制台**：未来只向管理员开放，保存非敏感配置和 Secret 引用，例如服务启停、供应商、模型、用途、每日/月度预算、最大并发、超时、有限重试、最近连通性、最近四位标识、用量和错误摘要。它不能“查看密钥”，测试连接也由后端使用 Secret 完成。

当前没有应用账号系统，因此首个内部可用版不建设可公开访问的自制管理员页面。推荐路径是：

- 本地开发默认使用 fake；获准测试真实 API 时，密钥只写入被 Git 忽略的本机 Secret/环境文件，不写数据库或仓库。
- 云端部署时由部署所有者在托管平台或专用 Secret 管理器中配置；网站只读取是否已配置和非敏感状态。
- 整个内部网站先置于身份感知代理、公司 VPN 或明确允许名单之后；若使用 Cloudflare Access，可对整站和未来 `/admin` 路径采用不同策略。没有入口保护时，不得因为“暂时没有账号”就把网站公开到互联网。
- 以后加入应用账号与管理员角色后，再实现网站业务控制台；是否允许从网站一次性替换密钥须另做权限、审计、CSRF、二次确认和 Secret 管理写权限审查。

### 8.2 员工发起任务时的调用链

`员工浏览器 → 本系统后端创建幂等任务 → PostgreSQL 保存任务/项目/术语版本 → Worker 领取任务 → 服务端读取 Secret → 调用供应商 API → 保存清洗后的结果、请求标识与用量 → 浏览器读取状态`

所有员工可以共享公司配置的供应商账户，但不是共享或分发原始密钥。后端必须统一执行并发上限、预算门禁、稳定幂等键、请求标识、有限重试和脱敏；余额不足、密钥失效或供应商限流时，员工只看到可操作的业务错误，不看到密钥、完整上游响应头或内部凭据。

术语提取、ASR 和未来 OCR 应使用不同用途的 Secret 引用与用量账本；开发、测试、生产也应使用不同密钥，避免一个泄露点影响所有环境。首版控制台配置不作为术语候选或识别结果的权威来源，任务必须保存实际使用的供应商、模型、配置快照和术语版本。

## 9. 可观察验收

S1 只有同时满足以下条件才算可工作，不按页面或代码数量计完成：

1. 一部 50–100 集匿名测试剧的已校验公司 SRT 可以按集数/轴号完整解析，单个坏文件会明确阻断并定位。
2. 候选覆盖八种正式类型规则；具名一次性角色不会仅因低频被静默遗漏。
3. 每个可审核候选至少有一条真实 SRT 证据，模型臆造项不能进入正式版本。
4. 全名、别称、职位称呼、地名优先、家族/公司边界、普通物品/疾病排除和类别唯一性均有回归案例。
5. 页面覆盖未提取、运行中、失败、空结果、待确认、已全部裁决、来源已变化和版本已确认状态。
6. 确认、修改、驳回、恢复、人工新增和批量操作刷新后仍一致；并发修改使用版本条件，不静默覆盖。
7. 当前页全选与“全部待确认”范围有明确区别；全部采用会分批处理所有 `pending`，任一失败时不创建版本、不下载文件，重试不会重复生成版本。
8. V1 确认后修改会形成新草稿，V1 内容不变；V2 只有再次显式确认后才出现。
9. 默认模板导出的正式 XLSX 五字段、别称分隔、空值、分组排序和示例行移除正确；自定义模板只改变五个表头名称和列顺序，历史导出绑定原模板版本且可重复生成同一结构。

13. 浏览器源码、网络响应和日志扫描不含供应商密钥；禁用或撤销 Secret 后任务以脱敏错误失败，不把未知结果标记成功。

## 10. 当前产品裁决与确认点

推荐把用户最新提示词固化为 `term-prompt-v1` 的业务规则来源，并采用本契约的“正式八类 + 全剧本地高召回 + AI 分类 + 真实证据校验 + 人工四态 + 不可变版本”组合。旧应用的 17 类只作为内部映射，不再直接暴露给员工。

用户已确认本草案，并进一步确认“全部待确认候选一键采用并导出”及公司级、版本化的五字段导出模板方向。规划将同一纵向切片拆为 `UI-M3-01`、`BACK-M3-01A`、独立模板后端任务 `BACK-M3-01C` 和后继 `FRONT-M3-01B`；前端必须等待 UI 更新与两项后端任务分别通过规划审核。任何任务不得把 ASR、OCR、视频播放器或任务中心塞入 S1。
