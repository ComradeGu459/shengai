# 全产品三轨路线图与进度口径

状态：规划权威基线 v3  
最后更新：2026-08-19

## 1. 为什么采用三轨口径

本项目的“完整产品”不是只有员工工作台。以后所有阶段简报、工期判断和完成比例统一同时计算：

1. **员工生产网站（60%）**：项目、素材、上传、术语、ASR/OCR、前置审改、字幕验收、任务中心和交付产品库。
2. **管理员系统控制台（20%）**：引擎/API、路由、提示词/热词/风险词、预算、用量、日志、学习候选、服务器与 Worker 运行管理。
3. **两站对接与真实生产化（20%）**：管理配置到业务 Worker 的生效链路、真实供应商、身份隔离、部署、对象存储、监控、真实样本和跨模块失效恢复。

三条轨道使用同一模块化后端和 PostgreSQL 权威事实，但拥有独立前端入口、访问策略和 API 权限域。不能用“员工页面已完成”代替“管理员网站与真实接入已完成”，也不能用设计文档或 Adapter 接口存在代替可运行产品。

## 2. 计分原则

- 进度只在形成可重复验收的运行结果后计入；规划、原型和预留接口只计少量地基分。
- 零网络 fake/stub 可以关闭员工业务状态机，但不计作真实供应商接入完成。
- 一个模块只有同时满足模块内部验收和 `MODULE_INTEGRATION_CONTRACTS.md` 的跨模块关闭门，才计入整链完成。
- 百分比用于判断范围和剩余工作，不是承诺精确到个位数的工时。

## 4. 后续执行顺序

### P1：关闭员工网站主链

1. S5 字幕验收与 S7 交付确认/产品库已经关闭；其冻结证据不在 S6 重做。
2. S6 已用获准真实素材跑通项目 → 上传 → 术语 → ASR/OCR → 前置审改 → 字幕验收 → 交付产品，并关闭两项真实流程缺口。
3. `M3-08` 统一任务中心已通过正式 Fastify、production frontend、从零隔离 PostgreSQL、系统 Chrome 与唯一完整质量门并关闭。

### P2：统一任务中心与 ControlShell

用户已确认 ControlShell 采用成熟企业控制台的“日间控制舱”方向，并以系统总览图的信息完整度作为最低基线。后续按以下顺序交付：

1. 先冻结统一任务中心与 ControlShell 的页面/状态/双视口 UI；ControlShell 必须包含独立路由和构建入口，员工 `AppShell` 不出现控制台导航。
2. 管理 API 独立权限域与两个 Access audience 的本地可测校验骨架。
3. 引擎登记、连接测试、主备路由与并发生效版本和回滚已由 SYSTEM-03 关闭；独立预算版本、调用前预留、硬阻断和待对账占用已由 SYSTEM-04 关闭，且未与路由容量双写。
4. Attempt/Usage/队列/Worker/存储/服务器只读总览及请求标识追踪；总览至少真实呈现 ASR API、OCR API、OCR 自建 Worker 和交付生成四个资源池。
5. SYSTEM-05 已关闭密钥与安全引用；SYSTEM-04CNY 已关闭人民币主账本与原币审计边界。真实 Secret、汇率网络、供应商网络和付费试跑仍走单独授权门。
6. 服务器/Worker 运行详情与统一日志已关闭；用户已确认 `PLAN-SYSTEM-07`：Wave A 证据目录/版本库已启动，Wave B 候选/离线评测和 Wave C 逐模块人工批准生效/回滚依赖后置。学习结果始终不得自动发布生产规则。

### P3：真实 API 与内部部署

在 SYSTEM-04 预算安全门关闭，且用户另行批准供应商、密钥、付费上限、服务器和样本后：

1. `SYSTEM-08` 已关闭：两站一键反馈、管理员流转、脱敏 requestId、显式截图附件和只追加历史已通过独立纵向与完整门；未做测试清单、自动截图或会话录像。
2. `PLAN-P3-01` 四角色只读准备审计已完成，唯一接入准备见 `docs/milestones/P3-real-asr-pilot-readiness.md`。当前真实付费调用为 `NO-GO`：需先补服务端受控小样本隔离和真实供应商运行时，并由用户确认供应商/区域留存/Secret引用/样本/人民币上限/质量门。
3. `SYSTEM-09` 已关闭：固定主备已升级为服务端有序执行目标链，ASR/OCR 的安全兜底、unknown 停止、逐 Attempt CNY 预算与历史审计已通过正式全链与唯一完整质量门；本地 OCR 可排第一，云 API 按成本/质量顺序后置。真实模型与供应商仍属于后续 P3 接入。详见 `docs/milestones/SYSTEM-ordered-execution-routing.md`。
4. 接入一个云 ASR 部署，用 1–3 集完成准确率、术语热词、时间轴、失败恢复和费用验收；推荐本机隔离环境按 `14 → 1 → 26` 分阶段执行，暂不购买服务器或接 COS/Sentry。
5. 用同一小样本比较本地 PaddleOCR、低价云 OCR 与高质量云 OCR，达到质量和费用门后再发布路由；随后复用共同路由原语接术语候选和需要 OCR/AI 的表格识别。
6. 部署员工域名和控制台域名，分别配置 Access Application/Audience，并验证管理 API 无法被员工身份调用。
7. 完成真实 COS、Sentry 脱敏错误观测、日志轮转、监控、备份、对象存储生命周期、付费用量对账和真实单剧全链验收。
