# 里程碑 2：项目与大文件上传生命周期

状态：范围已确认，等待技术选型门禁与里程碑 1 Git 基线。

## 目标

交付第一条可独立运行和验收的云端业务链路：员工创建项目，把项目素材安全直传到对象存储，能够查看、暂停、继续和恢复上传，并能把项目移入回收站、恢复或在 48 小时后清理。

本里程碑验证的是网站最底层的项目身份、文件边界和恢复能力。后续 ASR、OCR、术语和字幕审改全部在这一套项目与素材身份上接入。

## 范围

### 必须实现

- 项目创建、项目列表、项目详情和生命周期状态。
- 一个项目包含多个素材文件；原文件名只作为元数据展示，存储对象键由服务端生成。
- S3 兼容对象存储的短时授权、分片直传、完成确认和服务端校验。
- 浏览器内暂停、继续、刷新恢复、可重试失败和明确失败原因。
- 上传会话过期、主动取消和未完成分片清理。
- 项目回收站、48 小时恢复窗口、到期清理和清理审计记录。
- 项目、上传、文件和清理状态由后端统一提供；页面不得自行推断业务完成。
- 加载、空数据、失败、禁用、断网恢复和窄屏状态。

### 明确不做

- 账号、组织、角色、多租户和完整权限后台。
- ASR、OCR、AI、术语审核、字幕审改、内容合规和正式交付。
- 旧数据迁移、真实客户素材导入和本地应用写入。
- 微服务拆分、复杂消息队列和多云抽象层。
- 公开互联网匿名访问；没有账号的版本只能运行在本地或受控测试入口。

## 工作量与容量基线

- 员工峰值：不超过 10 人。
- 同时作业：约 5 人；并行项目或上传批次按 5–6 个设计。
- 日处理量：当前 10–20 部剧，容量参数允许后续提高。
- 单部剧：通常约 50 集，上限按 100 集；每集不超过 5 分钟。
- 单项目或批次：可能达到 10–30 GB。
- 默认回收保留：项目移入回收站后 48 小时。

这些数据是设计和验收输入，不是硬编码值。上传并发、单分片大小、会话有效期、回收期限和项目配额必须集中配置。

## 核心用户流程

1. 用户在项目中心创建项目。
2. 用户选择一个或多个匿名测试文件，浏览器向后端申请上传会话。
3. 后端生成对象键和分片上传授权，浏览器直接向对象存储发送文件内容。
4. 浏览器持续上报已完成分片；暂停时停止发起新分片，不删除已上传分片。
5. 用户刷新页面后，浏览器重新选择相同文件并通过文件指纹核对，继续缺失分片。
6. 浏览器请求完成上传；后端校验对象大小、分片结果和校验值后创建素材记录。
7. 项目全部必需素材校验完成后进入“可处理”。
8. 用户将项目移入回收站；48 小时内可以恢复。
9. 到期清理任务先标记清理中，再幂等删除对象和元数据引用，最终记录清理结果。

## 验收标准

- 项目中心、上传任务和回收站使用 `DESIGN.md` 中同一应用外壳和状态组件。
- 同一文件的重复完成请求不会创建重复素材或重复扣除存储配额。
- 刷新、短暂断网或后端重启后，已成功上传的分片不需要重传。
- 对象不存在、大小不符、校验失败、授权过期和会话过期均有不同且可操作的错误信息。
- 使用合成数据验证 5–6 个批次并行；在接入测试对象存储后，至少执行一次 10–30 GB 合成项目的容量演练。
- 回收站项目在 48 小时内可恢复；重复恢复和重复清理均安全。
- 清理失败不会把项目伪装为已删除，后台可以再次处理并保留失败原因。
- 可以发现并报告未完成分片、无数据库引用对象和缺失对象记录，禁止静默丢数据。
- `pnpm check` 通过，且不存在真实媒体、字幕、表格、数据库、密钥或环境文件进入 Git 候选集。

## 实施顺序

1. 完成技术选型 ADR，并建立里程碑 1 Git 基线。
2. 建立项目、素材、上传会话、上传分片和清理任务的数据模型与迁移。
3. 实现项目 API 和稳定错误结构。
4. 实现对象存储分片直传协议及本地测试替身。
5. 实现项目中心和上传队列，覆盖刷新恢复与失败状态。
6. 实现回收站、到期清理和孤儿数据核对。
7. 运行模块测试、构建、真实浏览器流程和合成大文件容量演练。
