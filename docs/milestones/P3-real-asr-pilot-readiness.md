# P3 真实 ASR 小样本接入准备

状态：等待用户确认真实供应商与授权输入；当前真实网络/Secret/付费调用为 `NO-GO`。

## 1. 目标与成功标准

只用获准的 1–3 集素材，在不影响员工正式任务、不移动生产当前路由的前提下，验证一个真实云 ASR 部署的准确率、术语热词、时间轴、失败恢复和人民币费用。只有质量、隔离、幂等、费用和历史证据全部通过，才允许另行批准发布。

首轮推荐按 `14 → 1 → 26` 分阶段执行；每集通过门后才允许显式开始下一集。三集总时长约 4.67 分钟。源 MP4/SRT 全程只读，不移动、改写或覆盖；仓库与普通日志只保存哈希、计数和脱敏身份，不保存字幕正文、视频帧或原始字节。

成功必须同时满足：

- 小样本只命中精确项目/集/Asset 白名单，员工正式任务调用数为 0；
- 外部付费请求不重复，unknown 只查询同一稳定身份；
- 每个 Attempt 的报价、预留、原币审计和 CNY 最终费用可对账；
- 供应商 Secret、内部引用、URL/Header、objectKey 与原始载荷不进入浏览器、数据库业务字段或日志；
- no-hotword 与 approved-hotword 使用同一时间窗成对比较；
- 质量达到用户确认的试跑门，且历史版本、请求、费用和恢复命令不可变。

## 2. 已具备、可直接复用

- 不可变 EngineDeployment/Version、Secret 安全引用与验证状态；
- connection test、路由草稿、影响检查、人工批准、发布/恢复和只追加审计；
- ASR Batch/Job/Attempt 固定 routingVersionId/deploymentVersionId，旧任务不会随新路由改写；
- 预算报价、CNY 主账本、原币审计、预留/结算/待对账和有界恢复；
- 员工 AppShell、管理员 ControlShell、统一任务中心、日志、预算、服务器与反馈入口；
- Modal/Drawer/ErrorBlock/CommandRecovery、1440/1024 响应式和两站权限隔离。

现有零网络 fake/stub 链已闭合，但它只能证明流程、幂等、恢复和预算语义，不能证明真实供应商质量或可用性。

## 3. 真实调用前的两个前置缺口

### P0：受控小样本隔离

当前 active routing 只按环境和工作阶段生效，普通发布会影响该阶段全部新任务。必须先新增服务端权威的试跑身份，至少固定：`trialRunId`、deployment/version、精确项目与 1–3 集 Asset 白名单、最大运行次数、预算策略/报价/CNY 上限和创建主体。

该试跑不得移动 active pointer，不得接收员工任务，不得出现在员工统一任务中心；POST 只允许一次，unknown 只 GET 同一 `trialRunId`。试跑完成只生成只读证据，不能自动批准或发布。

### P0：真实供应商运行时

必须补齐服务器端 provider adapter/Registry、按不可变 Secret 版本解析短时凭据的私有 resolver、受控 HTTP transport、UploadStorage 媒体流读取、真实 connection probe，以及 401/403、429、5xx、超时、响应丢失和供应商已受理但本地未知的统一状态映射。

浏览器不得提交明文 Secret、任意 endpoint、Header 或脚本。真实网络异常必须即时落入 `failed` 或 `reconciliation_required`，不能只依赖租约超时回收。若供应商只能 webhook/异步回调，必须先回规划补回调幂等与持久事实，不得临时用日志或前端状态代替。

### P1：观察和上线衔接

- 管理员页面明确区分“连接检查”和“1–3 集质量验证”；
- overview/logs/budgets 可按 `trialRunId` 过滤并交叉核对；
- 发布确认只消费服务端权威试跑结果、精确样本、CNY 与绑定部署版本；
- 真实生产启用前，员工 ASR/任务详情补齐安全 providerRequestId、requestId、路由/部署版本和待对账投影；员工默认不展示金额，金额仍由管理员预算与日志拥有；
- 移除“服务正常”等前端硬编码，改读服务端健康事实。

## 4. 推荐执行环境

第一阶段使用本机隔离数据库、隔离项目和独立试跑身份；仅真实供应商请求经过获准网络。暂不购买小服务器，不接真实 COS/Sentry，也不改变员工正式路由。这样先以最低成本验证 API、质量、热词、时间轴、失败恢复和费用。

第一阶段通过后，再单独批准小服务器、HTTPS/Access、持久对象存储、真实 Worker 租约接管、Sentry 脱敏观测、备份和对账。真实服务器和 COS 不能替代第一阶段的质量门，第一阶段本地结果也不能替代部署验收。

## 5. 试跑质量与人民币止损

建议初始上限（等待用户确认）：每集 `¥10`，三集累计 `¥30`；每集调用前先 quote→reserve，任一报价、预留或可能最终金额超过上限即停止。pending/unknown 保留预留，不按 0 计算，不自动重新发起付费 POST。

建议试跑门（等待用户确认，不是生产 SLA）：

- 术语 recall/precision 各不低于 95%；
- 空白、重复、幻觉合计不高于 1%；
- 时间漂移 median 不高于 250ms、p95 不高于 500ms；
- 断句可读性通过率不低于 90%；
- 任一隐私泄露、跨项目污染、重复扣费或源字幕改写直接 `NO-GO`。

每集盲评开头/中段/结尾，并抽专名、快速语音、多人重叠、噪声等风险 Cue；no-hotword/with-hotword 使用同一窗口。两名评审独立标注，分歧才由第三人裁决。WER 只作附加指标，不单独决定上线。

运行止损：排队 10 分钟未开始、15 分钟无首个结果、单集 30 分钟未终态时暂停该集，只允许同身份 GET/对账；401/403、连续两次 429、无法对账的 5xx/超时、Secret/正文泄露、第二 Attempt/Usage 或自动付费重发均立即停止。

## 6. 唯一实施顺序

1. 用户确认供应商、协议、区域/留存、Secret 引用方式、样本、预算和质量门。
2. 后端先实现 provider-neutral 的试跑隔离、私有 Secret resolver、受控 transport/媒体读取和错误映射；零网络回归先行。
3. 按供应商官方协议实现唯一 adapter 与真实 probe；不创建第二 ASR 写链或默认模型旁路。
4. 前端只消费后端权威 `trialRunId`、状态、费用和证据；不在浏览器推算是否可发布。
5. 测试先做 401/403、429、5xx、超时、响应丢失和 provider success/local unknown 故障注入，确认 POST=1、unknown 同 ID、预留不释放。
6. 依次执行 14、1、26；每集完成质量、费用和隐私人工门后再继续。
7. 规划汇总证据交用户裁决；试跑通过也不自动发布。
8. 用户另行批准后，才进入小服务器/COS/Access/Sentry 与生产路由发布。
