# 后端

当前使用 Fastify、TypeBox、`pg` 与 `node-pg-migrate`，提供 `/health`、项目创建/列表，以及项目素材清单读取与确认。PostgreSQL 是项目和已确认素材清单的唯一权威来源；项目创建和素材清单确认命令均要求 `Idempotency-Key`，素材确认同时校验预期版本。

上传模块已建立创建/读取会话、可续期分片授权、幂等分片确认、可恢复完成和幂等取消协议。PostgreSQL 保存上传会话、已确认分片、命令占位和最终素材绑定；完成阶段可在对象已合并但数据库落账中断后，用同一完成意图核对并恢复。内存 Storage fake 只在本地开发与匿名小型测试中模拟分片字节、合并、故障边界和对象校验。生产环境没有真实存储适配器时会拒绝启动，不能把 fake 当作生产存储。

项目生命周期模块提供幂等回收/恢复、回收站投影和 48 小时到期清理。`ProjectCleanupWorker.runOnce()` 是无内存业务状态的有界执行单元：从 PostgreSQL 获取租约，使用注入的 Storage 适配器做可重复删除，并把重试、失败原因和最终墓碑写回数据库。本地内存 fake 的字节状态不跨进程，因此本地验收在同一进程注入同一 fake；未来接入持久对象存储后可由独立 Worker 宿主复用该执行单元，不需要复制生命周期状态机。

业务代码按领域模块放入 `src/modules/<module>/`。HTTP、队列消费者、PostgreSQL 和对象存储适配器只能通过明确接口调用领域模块，不能各自维护业务状态。

运行迁移：`pnpm db:setup`。生产环境必须显式提供 `DATABASE_URL`；本地默认连接只在非生产环境生效。
